# 데이터 디렉터리

모든 게임 콘텐츠는 이 디렉터리의 JSON으로 관리한다. 몬스터·파츠·스킬을 추가할 때
**코드를 수정할 필요가 없다** — 파일에 항목을 넣고 검증기를 돌리면 끝이다.

## 파일

| 파일 | 내용 |
|---|---|
| `elements.json` | 7속성 정의 및 상성 배율표 |
| `skills.json` | 모든 스킬. 파츠·몬스터·모디파이어가 id로 참조 |
| `parts.json` | 골렘 파츠. 스탯 + 제공 스킬 + 드랍처 |
| `monsters.json` | 몬스터. 스탯 + 스킬 + AI + 드랍 파츠 |
| `modifiers.json` | 모디파이어 접두사. 스탯 배율 + 추가 스킬 |

## 검증

```
npm run validate
```

JSON 데이터 관리의 유일한 실질적 위험은 **오타 난 ID 참조가 런타임까지 발견되지 않는 것**이다.
검증기가 커밋 전에 이를 잡는다. 오류가 있으면 종료 코드 1로 실패한다.

검사 항목:

- **참조 무결성** — 파츠→스킬, 몬스터→스킬/파츠, 모디파이어→스킬, AI→보유 스킬
- **양방향 일치** — 몬스터의 `drops`와 파츠의 `drop_from`이 서로 맞는지
- **중복 id**
- **값 범위** — accuracy 1~100, 랭크 delta ±1~4, charges ≥1, lifesteal 0~1
- **열거값** — 속성, 슬롯, tier, 상태이상, effect op가 정의된 것인지
- **설계 규칙** — 몸통만 `def_element`를 가질 것(§5.3), 슬롯별 스킬 개수 상한(§3.1)
- **논리 오류** — 위력 0인데 효과도 없는 빈 스킬, 위력 0인 스킬의 lifesteal 등
- **고아 데이터** — 어디서도 참조되지 않는 스킬/파츠 (경고)
- **커버리지** — 속성별 스킬 분포, 몸통 방어 속성 분산 (경고)

경고는 실패시키지 않는다. 의도된 공백일 수 있기 때문이다.

## 밸런스 점검

```
npm run balance
```

§6.2의 턴수 목표에 데이터를 대고 검사한다. 몬스터 HP는 손으로 정하는 값이 아니라
**목표 턴수에서 역산되는 값**이므로, 수치를 바꿨다면 이 명령으로 확인한다.

`npm run check` 는 검증기와 밸런스 점검을 한 번에 돌린다.

## 새 몬스터 추가 예시

1. `skills.json`에 스킬 추가
2. `parts.json`에 드랍될 파츠 추가 (`drop_from`에 몬스터 id 기입)
3. `monsters.json`에 몬스터 추가 (`skills`, `drops`, `ai` 기입)
4. `npm run check` (참조 무결성 + 밸런스)

## 주의

- `id`는 한 번 정하면 바꾸지 않는다. 세이브 데이터가 id로 참조한다.
- 표시 이름은 `name`/`name_template`이 담당하므로 id는 영문 유지.
- `name_template`의 `{mod}`는 모디파이어 접두사, `{owner}`는 소유격이 런타임 삽입된다.
  모디파이어가 없으면 `{mod}`는 빈 문자열로 치환된다.
