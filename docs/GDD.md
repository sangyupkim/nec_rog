# Project Patchwork — 게임 기획서 v1.3

> 텍스트 UI 기반 턴제 로그라이트. 플레이어는 네크로맨서, 전투 주체는 몬스터 부속으로 조립한 **누더기 골렘**.
>
> 전투는 포켓몬식 커맨드 턴제 — 장착한 파츠가 곧 사용 가능한 스킬 목록이 되고, 매 턴 그중 하나를 골라 싸운다.

---

## 1. 게임 개요

| 항목 | 내용 |
|---|---|
| 플랫폼 | Web (HTML/CSS/JS, 빌드리스 or Vite) |
| 아트 | 이미지 에셋 최소화. 텍스트 + 유니코드 기호 + CSS만으로 표현 |
| 장르 | 커맨드 턴제 전략 로그라이트 / 파츠 크래프팅 |
| 1런 목표 시간 | 30~40분 (Act 1 프로토타입 12~15분) · 상한 관리는 §6.2 |
| 핵심 판타지 | "적을 죽여 그 시체로 내 병기를 만든다" |

### 1.1 디자인 원칙 (판단 기준)
1. **모든 스탯 변화는 파츠에서 나온다.** 골렘 자체는 빈 프레임이며 고유 스탯이 없다. → 빌드 = 장착 조합.
2. **텍스트가 곧 피드백.** 전투 로그가 UI의 주인공. 수치 변화는 로그 문장에 녹여 쓴다.
3. **매 턴 하나의 결정.** 손패도 자원 관리도 없다. "지금 어떤 스킬을 쓸 것인가" 한 가지에 집중시킨다.
4. **데이터 주도.** 몬스터/파츠/스킬/이벤트는 전부 JSON. 코드 수정 없이 콘텐츠 추가 가능.
5. **모디파이어로 곱셈.** 파츠 40개 × 모디파이어 12개 = 체감 수백 종.

## 2. 코어 루프

```
층의 방을 열어 탐험 (아이작식 격자 맵, 되돌아가기 자유)
   ↓
전투 (커맨드 턴제 배틀)
   ↓
전리품: 쓰러진 몬스터의 부위 해체 → 파츠 1~3개 중 택1
   ↓
작업대: 골렘 슬롯에 장착 / 교체 / 해체(재료화)
   ↓  (장착 = 스탯 + 사용 가능 스킬 변경)
다음 방 → ... → 보스방을 찾으면 다음 층
   ↓
사망 or 클리어 → 메타 재화 '영혼재(Soul Ash)' 정산
   ↓
납골당(거점) 귀환 → 방치 시설 정산·재가동 → 다음 런 출발 (§9)
```

루프는 두 층위로 겹쳐 돈다. **런 루프**(30~40분, 집중형)와 **거점 루프**(수 시간, 방치형)가 재료와 영혼재를 주고받는다.

**핵심 긴장 구조:** 파츠를 교체하면 스탯은 오르지만 **쓰던 스킬이 사라지고 새 스킬이 들어온다.** 공격력이 더 높은 팔로 갈아끼웠더니 유일한 화염 속성기가 사라져 특정 적을 못 잡게 되는 식이다. 스탯·속성 커버리지·내구도 세 축의 저울질이 이 게임의 주요 의사결정이다.

## 3. 골렘 조립 시스템

### 3.1 슬롯 구성 (5슬롯)

| 슬롯 | 주 기여 스탯 | 스킬 기여 | 비고 |
|---|---|---|---|
| 머리/코어 | 정신력, 통찰 | 0~1개 | 전투 시작 시 발동 패시브 |
| 몸통 | 방어도(가장 두껍다), 방어 속성 | 1개 (방어/버티기계) | 비워도 된다 — 대신 **핵이 드러난다** |

#### 3.1-A 흉곽 없이도 선다 — 대신 핵이 드러난다

전에는 몸통이 필수 슬롯이었다. 그래서 **팔다리는 멀쩡한데 흉곽만 없으면 아무것도 못 하는 교착**이 생겼다 —
부속을 둘 이상 들고 있으니 바르그는 돕지 않고, 몸통이 없으니 무덤에는 못 내려간다.
막다른 길을 만드는 규칙은 규칙이 아니라 버그다. 그래서 **몸통도 비울 수 있는 자리**가 됐다.

대신 값을 치른다. 몸통은 방어도가 가장 두꺼운 자리이므로 비우면 총량이 줄고,
거기에 더해 **들어온 피해의 35%가 방어도를 그냥 지나 핵에 꽂힌다**(`CORE_EXPOSED`).

| | 방어도가 받아낸 양 | 핵이 받은 양 |
|---|---|---|
| 흉곽 있음 | 182 | 0 |
| 흉곽 없음 | 88 | **48** |

<small>같은 공격 3회(위력 60, 주워 맞춘 핵 120)를 먹였을 때. 엔진으로 직접 측정.</small>

핵심은 **즉사가 아니라 자원의 교체**다. 핵은 그 피해를 체력으로 받아 낸다 —
흉곽 없이 내려가는 것은 "죽는다"가 아니라 **"핵의 내구도를 방어도 대신 태운다"**는 뜻이다.
급하면 그렇게라도 한 층을 돌 수 있고, 그 대가는 마을에서 핵을 고치는 시간이다.

**부속이 하나도 남지 않으면** 그때 강제 귀환한다 — 핵만 남은 것은 골렘이 아니다.
그것도 패배는 아니다. 핵과 남은 것은 그대로 안고 돌아온다.
패배의 대가(핵 파괴·부속 산실, §3.3)는 **핵이 0이 되거나 모든 부위가 무너졌을 때**의 것이다.
| 좌완 | 공격력 | 1~2개 | 무기 속성 부여 |
| 우완 | 공격력 | 1~2개 | 무기 속성 부여 |
| 다리 | 회피, 속도 | 1개 | 선공 판정 / 유틸 |

- **빈 슬롯 허용** (몸통 제외). 스킬이 줄어드는 대신 스탯 페널티 없이 가벼워지진 않으므로, 빈 슬롯은 기본적으로 손해다. 다만 "썩은 파츠를 억지로 끼우느니 비운다"는 선택지는 성립한다.
- 동시 보유 스킬 수: **5~9개**. 이 목록 전체가 매 턴 화면에 노출된다. 10개를 넘기면 선택 피로가 생기므로 상한 9로 제한.
- 스킬 상한 초과 시(파츠 조합이 9개를 넘길 때) 작업대에서 **봉인할 스킬을 직접 고른다.** 봉인된 스킬은 스탯 기여는 유지하되 전투에서 쓸 수 없다.

### 3.7 마력 — 핵이 감당할 수 있는 만큼만

부속은 등급마다 **마력**을 먹는다. 핵은 **품을 수 있는 마력**이 정해져 있고, 합이 넘으면 내려갈 수 없다.

| 등급 | 요구 마력 | | 핵 | 마력 |
|---|---|---|---|---|
| 일반 | 2 | | 주워 맞춘 핵 | 14 |
| 희귀 | 3 | | 실낱 심장 | 18 |
| 유니크 | 5 | | 무쇠 심장 | 22 |
| | | | 영혼 응결핵 | 32 |
| | | | 무덤군주의 핵 | 44 |

**대장간에서 핵을 강화한다** — 한 단계에 마력 +3, 최대 5단계. 강화는 **그 핵에만** 남으므로
갈아끼우면 새 핵의 단계를 따른다.

수치는 참조 빌드에 대고 맞췄다. **2부 초반이 제약이 처음 무는 지점** — 유니크를 다섯 개 들면
무쇠 심장(22)으로는 모자라 1~2단계를 강화해야 한다. 1부와 3부는 핵이 넉넉해 걸리지 않는다.
좋은 것을 주웠다고 바로 다 낄 수는 없다는 것이 요점이고, 그 벽이 오는 자리를 여기로 잡았다.

### 3.2 스탯 산출식

```
maxHP    = 핵.hp                              // 체력은 오직 핵에서 나온다 (§5.7)
attack   = Σ(파츠.atk)                        // 스킬 위력에 곱해짐
defense  = Σ(파츠.def)                        // 피해 감산
evasion  = min(60, Σ(파츠.eva))               // % 회피, 하드캡 60
speed    = Σ(파츠.spd)                        // 선후공 판정
focus    = Σ(파츠.focus)                      // 스킬 충전 회복 및 명중 보정
```

데미지 공식:
```
raw   = 스킬.power × (25 + attack) / 50 × 랭크배율(공격)
감산  = raw × (대상.defense × 랭크배율(방어)) / (대상.defense × 랭크배율(방어) + 40)
최종  = floor( (raw - 감산) × 속성배율 × 급소배율 ) 
```
- **공격력 25가 기준선.** 그 지점에서 `raw = 스킬 위력`이 된다. Act 1 골렘의 공격력은 6→23으로 자라므로 배율은 0.62→0.96 — 성장 폭을 1.5배 이내로 눌러 몬스터 HP가 폭주하지 않게 한다.
- `defense 40`에서 정확히 50% 감산. 방어 스탯은 수확체감이라 탱커 빌드가 무한정 굳지 않는다.
- 급소(치명타): 기본 5%, 배율 1.5.
- 회피 판정은 데미지 계산 이전에 수행 (`evasion - 상대 focus/2`).

### 3.3 내구도 (Integrity)

#### 무너지면 짐도 흘린다
골렘이 부서지면 **장착했던 부속**은 확률로 날아가고(내구도가 성할수록 잘 건진다),
**소지품에 들고 내려간 여분도 하나당 20%씩 흘린다.**

여분까지 거는 이유는 단순하다 — 그러지 않으면 여분을 잔뜩 쟁여두는 것만으로 죽음이 무손실이 된다.
교체용 부속을 들고 내려가는 것 자체가 도박이 되어야, 표본실에 맡기는 선택에 무게가 실린다.

제단의 **잔해 수습** 해금이 이 확률도 낮춘다(단마다 −4%p, 최하 5%).
계산은 `rollSpareLoss()` — 순수 함수라 화면을 거치지 않고 바로 재볼 수 있다.


시체 부속이라는 컨셉을 기계적으로 살리는 장치.

- 모든 파츠는 `integrity` 3~8 보유.
- **전투 종료 시** 해당 전투에서 스킬을 사용한 파츠는 내구도 -1. (사용하지 않은 파츠는 닳지 않는다 → 스킬 선택에 장기적 무게가 실린다.)
- 내구도 5 이하부터 UI에 경고 표시, 2 이하는 적색.
- **내구도 0 → 파츠 소실.** 슬롯이 비고, 해당 파츠의 스탯과 스킬이 즉시 사라진다. 전투 중이라면 전투 종료 후 처리.

#### 소실 방지 / 회복 수단 (네크로맨서의 도구)
파츠 소실은 강력한 압박이므로, 그것을 관리하는 것 자체를 플레이의 축으로 만든다.

| 수단 | 분류 | 효과 |
|---|---|---|
| 역청(Bitumen) | 소모품 | 파츠 1개 내구도 +3 |
| 방부 처리 | 안치실 선택지 (§6.7) | 파츠 1개 내구도 완전 회복 |
| 불멸의 봉인 | 유물(런 지속) | 지정 파츠 1개는 내구도 0이 되어도 소실되지 않고 1에서 멈춤 |
| 시체 방부제 | 유물 | 모든 파츠의 내구도 감소가 2전투당 1회로 감소 |
| 영혼 고정못 | 유물 | 소실 발생 시 1회에 한해 내구도 3으로 복원하고 소모 |
| 해체 | 작업대 | 소실 직전 파츠를 자발적으로 해체해 재료 획득 (손해를 통제된 이득으로 전환) |

> 설계 의도: "강한 파츠는 쓸수록 사라진다"는 자원 압박을 만들되, 네크로맨서의 도구로 그 압박을 관리·연장하는 것이 메타 성장의 방향이 된다.

### 3.5 골렘 핵 (Core)

골렘은 **핵 + 5슬롯 파츠**다. 파츠가 능력이라면 핵은 **골렘이 존재한다는 사실 자체**다.

- 핵이 없으면 조립할 수 없고, 무덤에 내려갈 수 없다.
- **패배하면 핵이 깨진다.** 그 골렘은 끝이고, 새 핵을 구해 처음부터 다시 세워야 한다.
- **핵이 곧 골렘의 체력이다.** 파츠는 체력을 주지 않고, 대신 방어도를 준다(§5.7).
- 핵의 체력은 **런을 넘어 남는다.** 반쯤 깎인 채로 다시 내려가면 그만큼 불리하다.

| 핵 | 출처 | 체력 | 능력 보정 |
|---|---|---|---|
| 주워 맞춘 핵 | NPC 무료 · 상점 160 | 120 | 없음 |
| 무쇠 심장 | 상점 420 | 190 | 방어+4 속도−2 |
| 실낱 심장 | 상점 400 | 130 | 속도+8 회피+5 집중+2 |
| 영혼 응결핵 | 1·2층 보스 | 210 | 공격+4 방어+2 집중+6 |
| 무덤군주의 핵 | 3층 보스 | 280 | 공격+8 방어+6 회피+2 속도+2 |

#### 패배 시 해체
골렘이 무너지면 핵은 깨지고 장착 부속은 흩어진다. 도망치며 주울 수 있는 것만 건진다.

```
회수 확률 = 20% + 45% × (현재 내구도 / 최대 내구도)
```
성한 부속일수록 잘 건진다. 회수한 것은 **날것 상태**가 된다 — 급히 뜯어 왔기 때문이다.
회수 실패한 부속은 표본실에 기록으로 남아 '소생'의 재료가 된다.

> 설계 의도: 패배의 대가를 "런 하나 날림"이 아니라 **"골렘을 다시 세워야 함"**으로 만든다.
> 동시에 전부 잃지는 않게 해서, 다음 골렘이 이전 골렘의 잔해 위에 서도록 한다.

### 3.6 최소 장착 규칙

**부속을 2개 이상 끼우지 않으면 무덤에 내려갈 수 없다.** 몸통은 그중 하나로 반드시 포함된다.

핵만 있고 부속이 하나뿐인 골렘은 사실상 서 있기만 할 뿐 싸울 수 없다.
그 상태로 내려보내면 첫 전투에서 아무것도 못 하고 죽는다 — 플레이어가 자초한 실패가 아니라
게임이 막아 줬어야 할 실패다.

바르그(§10.2-B)의 지원 조건도 이 숫자에 맞춰져 있다.

### 3.4 미처리 파츠 (Raw)

전투에서 막 뜯어온 부속은 **날것**이다. 그대로 붙일 수는 있지만 제값을 하지 않는다.

| | 날것 | 정착 후 |
|---|---|---|
| 스탯 발휘 | 60% | 100% |
| 기술 사용 | 25% 확률로 불발 | 정상 |
| 내구도 소모 | 전투당 2 | 전투당 1 |

- **정착(Attune)** — **납골당 → 접합로 → 정착.** 시체 조각 8 + 진액 1, 20분. 날것 표식이 지워진다.
- 접합로는 **처음부터 열려 있다.** 전투 드랍이 전부 날것이므로 정착은 선택이 아니라 필수 경로이고,
  이것을 해금 뒤에 두면 첫 런의 전리품을 제대로 쓸 수 없다.
- 상점 구매품·봉인실 보상·접합로 산출물은 처음부터 정착된 상태다. **날것은 전투 드랍에만 붙는다.**

> 설계 의도: 던전에서 주운 것을 즉시 끼우는 선택을 **가능하되 비싸게** 만든다.
> 급하면 지금 붙이고 불발과 마모를 감수하거나, 마을로 돌아가 제대로 처리하고 오거나.
> 이 저울질이 "언제 돌아갈 것인가"라는 §6의 탐험 결정과 맞물린다.

## 5. 전투 시스템 (커맨드 턴제)

포켓몬식 1:1 커맨드 배틀. 매 턴 플레이어는 **보유 스킬 목록에서 하나를 선택**하고, 양측의 speed로 실행 순서가 정해진다.

### 5.1 턴 구조
```
전투 시작
  → 코어 패시브 발동 / 적 등장 텍스트
반복 {
  ① 커맨드 선택   : 스킬 / 아이템 / 관찰(적 정보 열람)
  ② 순서 결정     : priority 우선 → speed 비교 → 동률 시 랜덤
  ③ 선공측 행동   : 명중·회피 판정 → 피해/효과 적용 → 사망 체크
  ④ 후공측 행동   : (사망 시 생략)
  ⑤ 턴 종료 처리  : 상태이상 틱 → 지속시간 감소 → 스킬 충전 회복
}
→ 한쪽 HP 0
```

- **적 행동은 예고되지 않는다.** 대신 `관찰` 커맨드로 적의 속성 약점·행동 패턴을 1회 열람할 수 있다(그 턴은 행동 소모). 정보와 템포를 맞바꾸는 선택.
- 도주 없음 (로그라이트 특성상).

#### 적은 내 상태를 읽는다
무작위로 때리는 적 앞에서는 조준도 방어도 관리도 팽팽해지지 않는다.
데이터의 가중치·패턴 위에 `intentBonus()`가 다음을 곱한다.

| 내 상태 | 적의 반응 |
|---|---|
| 핵이 35% 이하 | 보조기를 접고 화력을 든다 (공격기 ×1.6, 비공격기 ×0.3) |
| 방어도가 25% 이하 | 한 방이 큰 단타를 고른다 (×1.4) — 넘치는 만큼 핵에 닿는다 |
| 방어도가 60% 이상 | 다타로 방어도를 빨리 깎는다 (×1.3) |
| 내 방어 속성 | 유리한 속성을 골라 든다 (×1.5 / 불리하면 ×0.5) |
| 이미 걸린 상태이상 | 다시 걸지 않는다 (×0.35) |
| 적 자신이 멀쩡할 때 | 자기 회복기를 쓰지 않는다 (×0.4 / 다치면 ×1.8) |

### 5.2 스킬 데이터 모델

| 필드 | 설명 |
|---|---|
| `power` | 위력. 0이면 비공격 스킬 |
| `element` | 속성 (아래 표) |
| `accuracy` | 명중률 % (기본 95) |
| `priority` | 우선도. 기본 0, 선제 스킬 +1 |
| `charges` | 전투당 사용 횟수. `null`이면 무제한 |
| `recharge` | N턴마다 충전 1 회복 (focus 스탯으로 단축) |
| `effects` | 상태이상 부여, 랭크 변화, 회복 등 |

**충전(Charge)이 자원이다.** 기본기(발톱 후려치기 등)는 무제한, 강력한 스킬은 전투당 2~3회. 에너지 총량 관리가 아니라 "이 강스킬을 지금 쓸까 아낄까"의 문제로 바뀐다.

### 5.3 속성 상성

7속성. 배율은 유리 1.5 / 불리 0.5 / 무효 0 (극소수).

| 공격 ↓ / 방어 → | 참격 | 타격 | 화염 | 냉기 | 독 | 부패 | 신성 |
|---|---|---|---|---|---|---|---|
| **참격** | – | 1.5 | – | – | – | 0.5 | – |
| **타격** | 1.5 | – | – | 1.5 | – | – | – |
| **화염** | – | – | 0.5 | 1.5 | – | 1.5 | – |
| **냉기** | – | – | 1.5 | 0.5 | – | – | – |
| **독** | 1.5 | – | – | – | 0.5 | 0.5 | – |
| **부패** | – | 1.5 | – | – | 1.5 | 0.5 | 0.5 |
| **신성** | – | – | – | – | – | 1.5 | 0 |

- 골렘의 **방어 속성**은 몸통 파츠가 결정한다. → 몸통 선택 = 방어 상성 선택.
- 골렘의 **공격 속성**은 스킬마다 개별. 양팔을 서로 다른 속성으로 맞추면 대응 폭이 넓어진다. → **다속성 범용 vs 단일속성 특화**가 빌드의 핵심 축.
- 신성 속성은 언데드인 골렘 자신에게 치명적(적 성직자 계열이 사용). 부패는 신성에 무효 — 언데드 컨셉의 상성 반영.

### 5.4 능력 랭크 변화

포켓몬의 능력 랭크와 동일. `공격 / 방어 / 속도 / 회피` 4종, 범위 **-4 ~ +4**.

| 랭크 | -4 | -3 | -2 | -1 | 0 | +1 | +2 | +3 | +4 |
|---|---|---|---|---|---|---|---|---|---|
| 배율 | 0.5 | 0.57 | 0.67 | 0.8 | 1.0 | 1.25 | 1.5 | 1.75 | 2.0 |

- 랭크는 전투 종료 시 초기화.
- 버프 중첩형 빌드(광란의 파츠 등)가 성립하는 근거.

### 5.5 상태이상 8종

| 이름 | 효과 | 지속 |
|---|---|---|
| 중독 | 턴 종료 시 스택만큼 피해, 스택 -1 | 소모형 |
| 화상 | 턴 종료 시 최대HP 5% 피해 + 공격 -25% | 3턴 |
| 균열 | 받는 피해 +50% | 2턴 |
| 마비 | 25% 확률로 행동 불가, 속도 반감 | 3턴 |
| 공포 | 공격 스킬 사용 불가 (보조만 가능) | 1턴 |
| 재생 | 턴 종료 시 최대HP 8% 회복 | 3턴 |
| 가시 | 피격 시 반사 피해 | 전투 지속 |
| 봉인 | 마지막에 쓴 스킬 사용 불가 | 3턴 |

- 동일 상태이상 재부여 시 지속시간 갱신(중독만 스택 누적, 상한 10).

### 5.6 커맨드 UI 원칙
- 스킬 목록은 항상 전부 표시. 숨김·랜덤 요소 없음.
- 각 스킬 옆에 `속성 · 위력 · 남은 충전`을 상시 노출.
- 상성이 **판명된 뒤에는** 유리/불리를 스킬 옆에 아이콘으로 표기(첫 조우 시엔 미표기 → 학습이 진행이 된다).

### 5.7 방어도와 조준 (Shield)

**핵이 체력이고, 파츠는 그 앞을 막아서는 방어도다.**
피해는 방어도를 먼저 깎고, 방어도가 다 닳아야 핵에 닿는다.

```
부위 방어도 = 기본치[부위] + 파츠.def × 6 + 파츠.hp / 6
기본치 — 머리 80 · 몸통 160 · 팔 110 · 다리 110
```

| | 핵 체력 | 방어도 | 유효 |
|---|---|---|---|
| 1층 시작 골렘 | 120 | 457 | 577 |
| 2층 중반 골렘 | 190 | 약 520 | 약 710 |
| 3층 후반 골렘 | 280 | 약 640 | 약 920 |

#### 세 가지 규칙이 이 시스템의 전부다

1. **방어도가 먼저 닳는다.** 조준된 부위가 먼저 맞고, 그 부위가 바닥나면 남은 부위가 이어 받는다.
2. **부위 방어도 0 → 기능 정지.** 그 파츠가 주는 기술을 쓸 수 없다. 모든 부위가 무너지면 핵이 남아 있어도 패배한다.
3. **방어도는 포션으로 돌아오지 않는다.** 전투가 끝나도, 런이 끝나도 닳은 채로 남는다. 수리해야 돌아온다.

3번이 핵심이다. 방어도가 소모성 자원이 되면서 **"몇 층까지 버틸 수 있는가"가 물약 개수가 아니라 정비 상태로 결정된다.**

#### 회복 경로

| 수단 | 대상 | 비용 | 시간 |
|---|---|---|---|
| 시체 기름 (포션) | **핵만** | 소모품 | 즉시 |
| 안치실 휴식 | **핵만** (30%) | — | 즉시 |
| 던전 작업대방 | 방어도 **한 부위** | 시체 조각 (방어도 35당 1) | 즉시 · **방마다 한 번** |
| 납골당 정비대 · 방어도 재건 | 방어도 전부 | 조각 40 + 골분 4 | 40분 |
| 납골당 정비대 · 핵 안정화 | 핵 전부 | 진액 5 + 골분 4 | 60분 |

던전 안에서는 작업대방에서만 방어도를 되돌릴 수 있고, 값은 싸지만 재료를 먹는다.
납골당 정비대는 전부 한 번에 되돌리지만 시간이 걸린다 — 급하면 무덤에서, 여유가 있으면 거점에서.

#### 조준
커맨드 목록의 토글 하나로 전환한다. 매 턴 클릭이 늘지 않게 한 선택이다.

| 조준 | 대상 | 명중 | 부위 피해 |
|---|---|---|---|
| 무작위 | 전부 | ±0 | ×1.0 |
| 상단 | 머리 · 양팔 | −15 | ×1.5 |
| 하단 | 몸통 · 다리 | −10 | ×1.3 |

#### 몬스터의 부위
몬스터는 골렘이 아니므로 방어도가 아니라 **부위 체력**을 가지며, 파괴는 능력 저하로 나타난다.
부위 체력은 최대 HP 비례(머리 0.45 · 몸통 0.85 · 팔 0.55 · 다리 0.48).

| 부서진 부위 | 효과 |
|---|---|
| 팔 | 공격력 절반 |
| 다리 | 속도·회피 절반 |
| 머리 | 집중 60% 감소 |
| 몸통 | 방어 절반 |

**그리고 부서진 부위는 전리품에서 빠진다.** 이것이 조준의 핵심 교환이다 —
팔을 부수면 적의 공격이 반으로 줄지만, 그 팔은 부속으로 얻을 수 없다.
무작위 조준은 부위 피해 배율이 1.0이라 사실상 부속을 보존하는 선택이 된다.

#### 방어도를 지나치는 것들
피해는 방어도를 먼저 깎지만, **세 가지는 방어도를 지나쳐 핵을 직접 갉는다** — 중독, 화상, 가시.
갑옷 틈으로 스며드는 것이므로 설정과도 맞고, "방어도만 두껍게 쌓으면 된다"를 막는 장치이기도 하다.

방어도가 남았는데 핵이 줄어 있으면 플레이어는 버그로 읽는다. 그래서 로그 문장에 그렇게 적는다 —
*"독이 이음새를 타고 흘러 핵을 3 갉는다. (방어도를 지나친다)"*

**패배 조건은 둘이고, 둘 다 즉시 성립한다.**
① 핵이 0 — 부속이 전부 멀쩡해도 진다. ② 모든 부위의 방어가 무너짐 — 핵이 남아도 진다.

### 5.8 전투 텍스트 로그
모든 행동은 로그 라인으로 출력. 랜덤 동사 풀로 반복감 완화.
```
> 골렘이 [녹슨 도끼팔]을 휘두른다. 고블린이 14의 피해를 입는다.
> 효과가 굉장했다!
> 독을 품은 고블린의 송곳니가 골렘의 이음새를 파고든다. (9 피해, 중독 2)
> 고블린이 쓰러진다. 남은 것은 아직 경련하는 다리 한 쌍.
```

#### 로그를 쏟지 말고 주고받게 — 연출 박자
한 턴의 결과를 한꺼번에 쏟으면 **버튼을 누른 순간 로그가 여덟 줄 늘어나고, 무슨 일이 있었는지 되짚는 데 시간이 걸린다.**
턴제의 맛은 주고받는 순서가 눈에 보이는 데서 나오므로, 로그를 **국면(phase)별로 끊어** 흘린다.

- `Combat.say()`는 모든 줄에 현재 국면을 찍는다: `intro / summon / golem / enemy / end`.
  국면은 `act()`가 행동을 넘길 때마다 바꾼다 — 소환수 → 골렘 → 적 → 턴 끝.
- `UI.logPlay()`가 그 줄들을 재생한다. **같은 국면 안에서는 110ms, 국면이 바뀔 때는 420ms** 쉰다.
  결과적으로 "내가 때린다 → (약 0.5초) → 적이 때린다 → 내 턴" 의 박자가 생긴다.
- 타격이 들어간 줄에는 `hit: 'mon' | 'golem'` 이 붙고, 그 줄이 뜨는 순간 화면이 흔들린다.
  **적이 맞으면 가볍게(가로 흔들림), 내 골렘이 맞으면 크게(2축 흔들림 + 붉은 섬광).**
  누가 맞았는지 로그를 읽기 전에 몸으로 먼저 안다. 급소·핵 피해 줄은 `big`으로 한 번 더 튄다.
- 연출이 도는 동안 선택지 자리에는 `· · · 아무 곳이나 눌러 건너뛰기` 표시가 선다.
  버튼이 사라졌다 나타나며 화면이 튀지 않게 **자리를 지키는** 것이 핵심이다.
- **아무 곳이나 누르거나 아무 키나 누르면 남은 줄이 즉시 전부 나온다.** 연출은 기다림이 되어선 안 된다.
- `prefers-reduced-motion: reduce` 이면 흔들림·섬광·페이드를 모두 끈다.

> 구현 주의: `resolve()`가 `async`가 된다. 연출 중에는 선택지와 단축키가 비어 있으므로
> 그 사이에 다음 행동이 끼어들 수 없다. 자동 테스트도 클릭 후 `#choices .waiting`이
> 사라질 때까지 기다려야 한다 — 그러지 않으면 "선택지가 없다"고 보고 멈춘다.

## 6. 맵 & 진행 (아이작식 층 탐험)

각 층은 **시드로 생성된 유한한 방 격자**다. 플레이어는 문을 열어 인접한 방으로 이동하고, 자유롭게 되돌아갈 수 있으며, 원한다면 층 전체를 뒤질 수 있다. 보스방을 열고 들어가면 다음 층으로 내려간다.

### 6.1 왜 이 방식인가

StS식 분기맵과 아이작식 탐험의 본질적 차이는 선택의 성격이다.

| | 선택의 성격 |
|---|---|
| StS식 | **배타적 선택** — 하나를 고르면 나머지는 영영 포기 |
| 아이작식 | **자원 소모** — 전부 가질 수 있으나 대가를 치른다 |

아이작식이 성립하려면 "탐험할수록 비싸지는" 자원이 있어야 한다. 이 게임에는 **내구도(§3.3)**가 이미 그 자리에 있다.

- StS식에서 내구도는 수동적 페널티다. 지나가면 닳고 캠프파이어에서 고치는 것.
- 아이작식에서 내구도는 **탐험의 화폐**가 된다. 방 하나를 더 열 때마다 "도끼팔 내구도가 2다. 한 번 더 싸우면 1, 두 번이면 소실. 보스방은 아직 못 찾았다 — 지금 멈출까?"라는 계산이 붙는다.

내구도 소실 압박을 매 방의 실질적 결정으로 전환하는 것, 이것이 채택의 유일하고 결정적인 이유다. 부차적으로는 ① 묘지를 *뒤지는* 네크로맨서 컨셉과의 정합성, ② 적 의도를 숨기는 전투 설계(§5.1)와 "모르는 문을 연다"는 탐험 설계의 일관성이 있다.

### 6.2 런 길이 통제 — 최우선 제약

**이 방식의 유일한 치명적 위험은 런 길이다.** 커맨드 턴제 전투는 StS 전투보다 길고(6~10턴), 방을 전부 돌면 전투 횟수가 배로 늘어난다. 방치하면 런 하나가 90분이 된다.

따라서 아래 수치는 **디자인 목표가 아니라 지켜야 할 상한**이다.

| 항목 | 목표치 |
|---|---|
| 1런 총 길이 | 30~40분 (Act 1 프로토타입은 12~15분) |
| 층당 방 개수 | 9~12개 |
| 층당 전투방 | 4~6개 (전체의 절반 이하) |
| 일반 전투 소요 턴 | **4~6턴** |
| 엘리트 전투 소요 턴 | 8~12턴 |
| 보스 전투 소요 턴 | 15~20턴 |
| 100% 탐험 시 추가 시간 | 기본 경로 대비 +60% 이내 |

두 가지 규칙이 이 상한을 지킨다.

1. **빈 방을 만들지 않는다.** 아이작의 빈 방은 3초면 지나가지만, 텍스트로 "아무것도 없는 방입니다"를 스무 번 읽는 것은 그냥 지루하다. 모든 방은 전투·이벤트·자원·함정 중 하나를 반드시 가진다. 통로 역할의 방이 필요하면 **짧은 분위기 텍스트 한 줄 + 즉시 통과**로 처리하고 방 개수에 세지 않는다.
2. **몬스터 HP는 턴수 목표에서 역산한다.** §7의 수치는 StS식 전제로 잡은 것이므로 전면 재조정 대상이다 (§6.8).

### 6.3 층 구조

```
        ┌─────┐
        │  ?  │
        └──┬──┘
┌─────┐ ┌──┴──┐ ┌─────┐ ┌─────┐
│  ⚔  ├─┤ 시작├─┤  ⚔  ├─┤  🔨 │
└──┬──┘ └─────┘ └──┬──┘ └─────┘
┌──┴──┐          ┌─┴───┐
│  🔒 │          │  ☠  │
└─────┘          └──┬──┘
                 ┌──┴──┐
                 │  👑 │
                 └─────┘
```

- **격자 기반.** 각 방은 (x, y) 좌표를 가지며 상하좌우 4방향으로 인접 방과 연결된다.
- **되돌아가기 자유.** 이미 지난 방은 언제든 다시 지날 수 있고, 클리어된 전투방은 재전투가 없다.
- 이동은 **화면 기준 방향**(↑ 위 · → 오른쪽 · ↓ 아래 · ← 왼쪽)으로 표기하고, **키보드 방향키**로도 움직인다. 동서남북은 미니맵과 머릿속에서 한 번 더 변환해야 해서 버렸다.
- **보스방을 열면 그 층은 끝난다.** 들어가기 전 "아직 탐험하지 않은 방이 N개 남았습니다" 경고를 띄운다 — 되돌아갈 마지막 기회를 명시적으로 준다.

### 6.4 방 타입

| 기호 | 방 | 층당 개수 | 내용 |
|---|---|---|---|
| ⚔ | 전투방 | 4~6 | 일반 몬스터 1~2체. 클리어 시 파츠 드랍 |
| ☠ | 엘리트방 | 1~2 | 강적. 확정 희귀 파츠 + 모디파이어 보장 |
| ? | 이벤트방 | 1~2 | 텍스트 선택형 (§7.3) |
| 🔨 | 작업대방 | 1 | **던전에서 파츠를 교체할 수 있는 유일한 곳** (한 번만 · §6.4-A) |
| 🔥 | 안치실 | 0~1 | 휴식/방부 처리/개조 (구 캠프파이어, §6.7) |
| 🔒 | 봉인실 | 0~2 | 재료를 바쳐야 열린다 (§6.5) |
| 💀 | 유해 더미 | 1~2 | 전투 없이 재료 획득. 거점 자원(§9.2) 수급처 |
| ⚠ | 함정방 | 0~2 | 즉시 대가를 치르고 통과 (§6.6) |
| 👑 | 보스방 | 1 | 층 보스. 클리어 시 다음 층 |

시작방은 항상 비어 있고 안전하다.

**던전에서는 작업대방에서만 정비할 수 있다.** 다른 방에서는 골렘 상태와 소지품을 열람만 한다.
그러지 않으면 작업대방이 존재할 이유가 없어진다. 마을에서는 언제든 자유롭게 정비한다.

#### 6.4-A 작업대는 한 번만 쓴다

작업대는 조각 몇 개로 **즉시** 고쳐 주는데, 납골당 정비대는 재료에 시간까지 든다.
제한이 없으면 **작업대 방을 찾는 것만이 정비의 정답**이 되고, 거점의 정비대는 아무도 쓰지 않는다.
그래서 작업대 하나가 해 주는 일은 **하나뿐**이다.

| 쓸 수 있는 것 | 내용 |
|---|---|
| 부속 한 자리 교체 | 슬롯 하나를 갈아끼우거나 떼어낸다 (핵 교체 포함) |
| 한 부위 방어도 수리 | 가장 급한 한 부위만 상한까지 되돌린다 |

- 둘 중 **하나를 쓰면 그 작업대는 끝난다.** 「작업대 — 다 썼다」로 남아 무엇에 썼는지 보여 준다.
- 쓴 기록은 **방에 새긴다**(`room.used`). 층을 넘기면 새 작업대가 생기고,
  같은 층에서 되돌아와도 이미 쓴 것은 쓴 것이다.
- 열람(골렘 상태·소지품·상성표)은 소모하지 않는다. 보는 것은 정비가 아니다.
- 마을에는 이 제한이 없다 — 거기서는 시간과 재료가 대신 값을 받는다.

### 6.5 봉인실 — 되돌아가기를 의미 있게 만드는 장치

**되돌아가기가 성립하려면 "지금은 못 열지만 나중엔 열 수 있는 문"이 필요하다.** 아이작의 백트래킹은 사실 열쇠와 폭탄 때문에 생긴다. 이것이 없으면 되돌아가기는 빈 복도를 다시 걷는 일에 불과하다.

봉인실은 세 종류다.

| 종류 | 여는 조건 | 보상 |
|---|---|---|
| 뼈 봉인 | 시체 조각 15 지불 | 희귀 파츠 확정 1개 |
| 속성 봉인 | 특정 속성 공격 스킬 보유 (예: 화염) | 해당 속성 유니크 파츠 |
| 피의 봉인 | 현재 HP의 25% 지불 | 모디파이어 표본 + 골분 |

- 봉인실은 **처음 발견했을 때 열지 못할 수 있다.** 재료가 모자라거나, 필요한 속성 스킬이 없거나. 그래서 층을 더 뒤지고 파츠를 바꾼 뒤 **돌아오게 된다.**
- 조건은 방 앞에서 항상 공개된다. "무엇이 필요한지"는 알려주되 "안에 무엇이 있는지"는 알려주지 않는다.
- 속성 봉인은 §5.3의 다속성 커버리지 설계와 직결된다 — 범용형 빌드가 탐험에서 보상받는 지점.

### 6.6 함정방

전투 없이 **즉시 대가를 치르고 지나가는** 방. 지나갈지 돌아갈지를 묻는 것이 목적이다.

- **붕괴한 천장** — 통과 시 골렘 HP 15% 피해
- **산성 웅덩이** — 통과 시 무작위 파츠 1개 내구도 -1
- **영혼 소용돌이** — 통과 시 능력 랭크 1개가 무작위로 -1 (다음 전투까지 지속)

함정방은 **지름길에 배치**되는 경우가 많다. 돌아가면 방 3개를 더 지나야 하고, 뚫으면 내구도 1을 낸다 — 이 교환이 함정방의 전부다.

### 6.7 안치실 (구 캠프파이어)

층당 0~1개. 없는 층도 있다는 점이 중요하다 — 있을 때의 가치가 올라간다.

1. **휴식** — 최대 HP의 30% 회복
2. **방부 처리** — 파츠 1개 내구도 완전 회복
3. **개조** — 파츠 1개에 모디파이어 랜덤 부여 (기존 것 덮어씀, 도박)

내구도가 탐험 화폐가 되었으므로 ①과 ②의 저울질은 "지금 살아남기 vs 더 탐험하기"의 직접적 교환이 된다.

### 6.8 층 생성 알고리즘 (시드 기반)

```
generateFloor(seed, floorIndex):
  1. 시작방을 격자 중앙에 배치
  2. 목표 방 개수 N = rand(9, 12)
  3. 무작위 보행으로 방을 N개까지 확장
     - 인접 방이 3개 이상인 칸에는 배치하지 않는다 (뭉치는 것 방지)
     - 층 전체가 한 덩어리로 연결되도록 보장
  4. 시작방에서 가장 먼 말단(leaf) 방을 보스방으로 지정
  5. 남은 말단 방에 우선 배치: 엘리트, 봉인실, 작업대
     (말단 = 막다른 길. 일부러 찾아가야 하는 방을 둔다)
  6. 나머지 방에 전투/유해더미/이벤트/함정을 쿼터 규칙(§6.4)에 맞춰 채움
  7. 검증: 전투방 4~6, 작업대 1, 보스방 1, 도달 불가 방 0
     → 실패 시 시드를 증분하고 재생성
```

- **시드 고정 = 층 재현.** 동일 시드에서 동일 층이 나온다. 버그 리포트와 밸런스 시뮬레이션에 필수.
- **보스방은 가장 먼 말단.** 자연스럽게 "보스를 찾는 과정 = 탐험"이 된다.
- **중요한 방은 말단에 둔다.** 지나가다 얻어걸리는 게 아니라 일부러 발을 들여야 얻도록.

### 6.9 미니맵

```
        [?]
         │
 [⚔]─[시작]─[⚔]─[🔨]
  │           │
 [🔒]        [☠]
              │
             [·]
```
- 방문한 방은 타입 기호, 인접했으나 미방문인 방은 `[·]`, 미발견 방은 공백.
- 봉인실은 발견 즉시 조건을 함께 표시: `[🔒 시체조각 15]`
- 현재 위치는 반전 표시. 이동은 방향키 또는 방 클릭.

### 6.10 Act 구성

| Act | 층 수 | 특징 |
|---|---|---|
| 1 | 3층 | 프로토타입 범위. 3층 보스 = 무덤군주 |
| 2 | 4층 | tier 2 모디파이어 해금, 봉인실 빈도 증가 |
| 3 | 4층 | 최종 보스 |

Act 1 기준 전투 횟수: 층당 전투 4~6 + 엘리트 1~2 × 3층 ≈ **15~22전투**. 일반 전투를 4~6턴으로 조이는 것이 전제이며, 그러지 않으면 이 구조는 성립하지 않는다.

### 7.3 밸런스 검증

> **가장 크게 틀렸던 것 — 근사가 두 번 거짓말을 했다.**
>
> 캠페인을 붙이고 나서 실제로 굴려 보니 **1-1을 아무도 깰 수 없었다.** 1층에서 3~4전투 만에
> 모든 부위의 방어가 무너졌다. 그런데 검사기는 "전투당 12% 소모, 5회면 59%"라며 통과시키고 있었다.
> 원인은 셋이었고, 셋 다 **모델이 실제를 흉내 내지 못한 것**이었다.
>
> 1. **회복 예산 125%를 가정했다.** 방어도에는 그런 것이 없다 — 작업대·정비대에서 재료를 써야만 돌아온다.
> 2. **전투 길이를 낙관했다.** "매 턴 가장 센 기술이 명중하고 부위는 무너지지 않는다"고 보았다.
>    실제로는 빗나가고, 부위가 무너져 기술이 사라진다. 근사가 18턴이라던 보스가 **33턴**이었다.
> 3. **도트가 방어도를 지나쳐 핵을 직접 갉는데**, 화상이 최대 체력의 5%였다.
>    20턴짜리 보스전이면 산수로 핵이 정확히 0이 된다. 실제로 부푼 어머니가
>    **방어도를 631 남긴 채 핵만 0으로** 만들고 있었다.
>
> 그래서 근사를 버렸다. **`npm run simulate`는 `src/combat.js`를 그대로 불러 진짜 전투를 돌린다.**
> 느리지만 거짓말은 하지 않는다. `npm run rebalance`도 같은 엔진으로 HP를 역산한다.
>
> **교훈: 밸런스 도구가 게임과 다른 모델을 쓰면, 그 도구는 틀린 답을 자신 있게 알려 준다.**

#### 세 가지 도구
| 명령 | 하는 일 | 권한 |
|---|---|---|
| `npm run validate` | 참조 무결성·설계 규칙 | 확정 |
| `npm run balance` | 데이터 개요와 어림셈 | **참고용** (낙관적) |
| `npm run simulate` | 실제 엔진으로 9단계 완주 검사 | **확정** |
| `npm run rebalance` | 실제 엔진으로 HP 역산 | 데이터를 고쳐 쓴다 |

#### 완주 목표
두 가지로 굴린다. **전부 탐험하는 쪽이 자주 실패해야 한다** — 안전하면 §6.1이 거짓말이 된다.

| 프로필 | 한 층에서 싸우는 횟수 | 목표 완주율 |
|---|---|---|
| 알뜰 (엘리트방을 지나침) | 전투 4 + 층의 주인 | 75% 이상 |
| 전부 (다 연다) | 전투 4 + 엘리트 + 층의 주인 | 30% 이상 |

#### 이 검사가 바꾼 수치
- 부위 방어도 기본값 **2배** (머리 160 / 몸통 320 / 팔·다리 220). 한 판이 아니라 **한 단계**를 버티는 예산이다.
- 작업대 수리 **조각 1당 방어도 35** (기존 15). 안치실에서도 같은 값으로 수리할 수 있게 했다.
- 유해 더미 산출 **조각 `int(6,14) + 층×3`**. 조각이 방어도를 되돌리는 유일한 수단이라 이 값이 완주 가능 여부를 정한다.
- 도트가 한 전투에서 핵에서 가져갈 수 있는 양을 **35%로 제한**하고, 화상을 최대 체력의 **3%**로 낮췄다.
- '층의 주인'은 전용 엘리트를 또 키우는 대신 **일반 몬스터를 키운 것**으로 바꿨다 (엘리트×1.2는 층 중간에 보스급을 세웠다).
- 시작 골렘이 **네 자리를 채운 채** 출발한다 (머리 추가). 세 자리로는 1-1의 첫 층을 못 넘겼다.
- 1-1은 **2층짜리**다. 첫 단계는 짧게 가르치고 끝내는 편이 낫다.


```
npm run balance
```

§6.2의 턴수 목표(일반 4~6 · 엘리트 8~12 · 보스 15~20)를 데이터에 대고 검사한다.
몬스터가 **처음 등장하는 층**의 참조 빌드로만 판정하며, 이전 층 몬스터가 나중에 빨리 죽는 것은 성장이 체감되는 정상 동작으로 본다.

함께 출력되는 `피격 N/턴 · M턴이면 골렘 사망`은 반대 방향 검증이다. 전투가 목표 턴수 안에 끝나더라도 골렘이 그 전에 죽으면 수치가 틀린 것이다. **전투 소요 턴 < 골렘 사망 턴** 이 항상 성립해야 한다.

수치를 바꿀 때는 이 명령을 먼저 돌린다. 몬스터 HP는 손으로 정하는 값이 아니라 턴수 목표에서 역산되는 값이다.

## 7-A. 캠페인 — 3부 9단계와 메인 퀘스트

로그라이트의 반복은 **반복할 이유**가 있어야 성립한다. 지금까지의 구조는 전투·파츠·방치가 모두 돌아가는데
"이걸 다 해서 무엇이 되는가"만 비어 있었다. 이 장이 그 자리를 채운다.

### 7-A.1 골격

**3개의 던전(파트) × 각 3단계 = 9단계, 9보스.**

| 파트 | 던전 | 성격 | 해금 조건 |
|---|---|---|---|
| **1부** | **시궁 아래 (하수도)** | 젖고 병들고 녹슨 곳. 시체골이 버리는 것들이 모인다 | 처음부터 |
| **2부** | **버려진 공동묘지** | 이름이 지워진 무덤들. 묻힌 것이 묻힌 채로 있지 않다 | 1부 3단계 보스 처치 |
| **3부** | **미궁** | 누가 왜 지었는지 모르는 인공 구조물. 골렘 기술의 원류 | 2부 3단계 보스 처치 |

각 파트의 1·2·3단계에는 **저마다 다른 보스**가 있고, 3단계 보스를 처음 쓰러뜨리면 다음 파트가 열린다.

#### 1단계 = 1런 = 3층 (핵심 결정)

"단계"를 무엇으로 셀 것인가에 세 가지 안이 있었다.

| 안 | 전체 분량 | 문제 |
|---|---|---|
| 1단계 = 1층 | 파트당 런 1회 = **총 3런** | 로그라이트의 반복 루프가 성립하지 않는다. 죽으면 3층을 통째로 다시 해야 하는데 보상 주기는 한 번뿐 |
| 1단계 = 1파트 | **총 3보스** | 사용자가 요청한 9보스 구조가 무너진다 |
| **1단계 = 1런 = 3층** ✅ | **총 9런** | 없음 — §6.2의 런 길이 상한(30~40분)을 그대로 유지한다 |

**채택: 1단계 = 3층짜리 런 한 번, 마지막 층의 보스방에 그 단계의 보스.**
9번의 완주가 캠페인의 최단 경로이며, 실제로는 재도전이 섞여 15~25런이 된다.
이것이 로그라이트의 반복과 캠페인의 목표를 동시에 만족시키는 유일한 배치다.

- 한 번 연 단계는 **언제든 다시 들어갈 수 있다.** 재료·파츠 파밍과 난이도 조절의 창구다.
- 죽으면 그 단계를 처음부터. 대신 §8의 메타 성장(영혼재·표본·해금)이 재도전의 출발선을 올린다.
- 메인 퀘스트는 항상 **다음 미개척 단계**를 가리킨다. "지금 무엇을 해야 하는가"가 늘 한 줄로 보이는 것이 목표 부각의 전부다.

### 7-A.2 파트별 환경 규칙 — 던전을 서로 다르게 만드는 것

몬스터만 갈아끼우면 세 던전은 같은 게임이 된다. **파트마다 층 전체에 걸리는 규칙을 하나씩** 둔다.
셋 다 §6.1의 "탐험은 자원 소모"라는 원칙을 각자의 배경으로 번역한 것이다.

| 파트 | 규칙 | 내용 | 무엇을 압박하는가 |
|---|---|---|---|
| 1부 | **범람** | 방을 열 때마다 수위가 오른다. 일정선을 넘으면 다리 파츠 내구도 소모 2배, 속도 −1랭크 | 시간. 오래 뒤질수록 비싸다 |
| 2부 | **망자의 시선** | 방을 열 때마다 '주시'가 쌓인다. 임계치에서 하수인이 난입해 추가 전투 | 100% 탐험의 대가를 전투로 청구 |
| 3부 | **재배치** | 방을 나서면 아직 가지 않은 방의 연결이 바뀐다. 미니맵이 일부 거짓을 말한다 | 되돌아가기 자체. 탐험의 안정성이 자원이 된다 |

단계가 올라가면 같은 규칙이 **더 빨리·더 세게** 걸린다. 1단계는 맛보기, 3단계는 이 규칙이 전투만큼 중요해진다.

### 7-A.3 단계별 난이도 축

각 파트 안에서 단계는 세 축으로만 올린다. 축을 늘리면 조절이 불가능해진다.

| 단계 | 몬스터 | 모디파이어 | 환경 규칙 |
|---|---|---|---|
| 1단계 | 그 파트 일반 몬스터 | tier 1 | 약하게, 안내와 함께 |
| 2단계 | + 엘리트 등장률 상승 | tier 1~2 | 본격적으로 |
| 3단계 | + 엘리트 상시 | tier 2 | 보스 전투에까지 개입 |

| **m_ornel** | **최초의 네크로맨서 오르넬** | **3단계 보스 · 최종** | 신성 + 부패 | 골렘을 처음 만든 자. 플레이어의 거울이자 이 게임의 종착 |

**볼륨**: 신규 20종(일반 10 · 엘리트 2 · 보스 8) → 총 27종. 스킬 약 +50개, 보스 유니크 파츠 보스당 2개씩 +16개.

### 7-A.5 메인 퀘스트 — 바르그가 전담한다

뼈 수습꾼 바르그(§10.2-B)는 이미 **튜토리얼·재화 안내·파츠 지원**을 맡고 있다.
여기에 메인 퀘스트를 얹는 이유는 단순하다 — **돌아올 곳이 하나여야 목표가 흐려지지 않는다.**
의뢰소의 반복 의뢰와 메인 퀘스트는 성격이 다르므로 창구를 나눈다.

| | 의뢰소 (§10.2-A) | 바르그 (§10.2-B) |
|---|---|---|
| 성격 | 반복 · 교체 가능 | **한 줄기 · 되돌릴 수 없음** |
| 단위 | 런 단위 목표 | 단계 단위 목표 |
| 보상 | 은화·재료 | 다음 단계 해금 · 영혼재 · 유니크 파츠 |

- 마을 화면과 바르그 메뉴 맨 위에 **현재 목표 한 줄**을 상시 표시한다. 목표 부각은 이 한 줄이 8할이다.
- 단계를 처음 클리어할 때만 이야기 비트가 재생된다. 재도전 시에는 나오지 않는다.
- 한 파트당 대사 비트 3~4개, 비트당 **4~6줄.** 텍스트 UI에서 긴 로어 문서는 읽히지 않는다 — 짧게, 자주.

### 7-A.6 이야기 — 가볍게, 세 마디로

**전제 하나만 깔고 간다.** 네크로맨서는 왜 시체로 골렘을 만드는가 — **되살리고 싶은 누군가가 있다.**
그게 누구인지는 3부까지 밝히지 않는다. 플레이어가 묻지 않아도 진행에 지장이 없고, 궁금해하면 답이 나온다.

**1부 · 「재료」** — 바르그의 수레가 어디서 오는지 밝혀진다. 하수도다. 그는 시체골이 버린 것들을 여기서 줍는다.
목표는 아직 단순하다: 쓸 만한 부속. 부푼 어머니를 쓰러뜨리면 바르그가 처음으로 이름 하나를 흘린다 —
*"예전에 나랑 같이 내려가던 사람이 있었지."*

**2부 · 「이름」** — 하수도의 시체들은 떠내려온 것이었다. 위에 공동묘지가 있다.
무덤군주는 묻힌 자들의 **이름을 전부 알고 있다.** 플레이어가 찾는 이름도.
그를 쓰러뜨리면 이름을 얻는다 — 그리고 **그 무덤이 비어 있다는 것도.**

**3부 · 「원형」** — 빈 무덤 아래에 미궁이 있다. 골렘 기술의 원류이자, 최초의 네크로맨서 오르넬이 남긴 것.
그도 같은 일을 했고 같은 실패를 했다. 마지막에 선택이 주어진다 — **되살릴 것인가, 놓아줄 것인가.**

- **엔딩 2개.** 분량 대비 효과가 가장 큰 장치다. 선택지 하나와 엔딩 텍스트 두 벌이면 된다.
- **바르그의 정체는 열어 둔다.** 왜 늙지 않는지, 왜 수레에 늘 딱 필요한 부속이 있는지 — 3부에서 한 줄로만 건드린다.
  오르넬의 첫 골렘이라는 해석과, 그저 오래 산 사람이라는 해석이 **둘 다 성립하게** 쓴다. 확정하면 값이 떨어진다.

## 9. 거점: 납골당 (The Ossuary)

> 런과 런 사이, 네크로맨서가 돌아오는 유일한 장소. 전투가 없는 대신 **시간이 자원인** 공간이다.

전투 루프가 "20분 집중"이라면 납골당은 "하루 두 번 들여다보는" 층위다. 두 층위가 서로를 먹여살린다 — 런에서 얻은 재료가 납골당의 연료가 되고, 납골당의 산출물이 다음 런의 출발선을 올린다.

### 9.1 웹 구현 가능성 검토 — **가능**

방치형의 본질은 "타이머를 돌리는 것"이 아니라 **두 시점 사이의 경과 시간을 계산하는 것**이다. 브라우저에서 전부 성립한다.

| 요구사항 | 웹에서의 해법 | 비고 |
|---|---|---|
| 앱을 꺼도 시간이 흐름 | 종료 시각 `lastSeenAt`을 저장, 재접속 시 `Date.now() - lastSeenAt`으로 일괄 정산 | 타이머를 계속 돌릴 필요가 전혀 없다 |
| 저장 | `localStorage` (JSON 수 KB 수준) | 5MB 한도 대비 여유. 용량 문제 없음 |
| 백그라운드 탭에서 정확도 | **`setInterval` 누적 방식 금지.** 백그라운드 탭은 타이머가 1분 단위로 스로틀링됨 | 화면 갱신용 틱과 실제 계산을 분리 |
| 여러 작업 동시 진행 | 각 작업이 `startedAt` + `durationMs`를 들고 있는 큐. 정산 시 완료 여부만 판정 | 작업 수만큼 타이머가 필요하지 않음 |
| 완료 알림 | `Notification API` (권한 필요) 또는 탭 제목 갱신 | 선택 기능. 없어도 게임은 성립 |
| 서버 | **불필요.** 전부 클라이언트 | 계정·랭킹을 붙일 때만 서버 필요 |

**핵심 구현 규칙 (설계에 못박아 둘 것)**
```js
// 정산은 반드시 경과 시간 기반. 틱 누적이 아니다.
const now = Date.now();
const elapsed = Math.max(0, Math.min(now - state.lastSeenAt, OFFLINE_CAP_MS));
settleAll(elapsed);   // 순수 함수: 상태 + 경과시간 → 새 상태
state.lastSeenAt = now;
```
- `Math.max(0, ...)`: 시스템 시계를 되돌렸을 때 음수 경과로 상태가 깨지는 것을 막는다.
- `OFFLINE_CAP_MS`: 오프라인 정산 상한. 초기 **8시간**, 납골당 확장으로 최대 **24시간**.
- `settleAll`은 DOM과 무관한 순수 함수 → 테스트에서 "72시간 경과" 같은 케이스를 즉시 검증할 수 있다.

> **치트에 대한 입장:** 시스템 시계를 앞당기면 시간을 벌 수 있다. 싱글플레이 웹게임이므로 이를 막기 위해 서버를 도입하지 않는다. 음수 경과 방어와 오프라인 상한, 두 가지만 지키고 나머지는 플레이어의 자유로 둔다.

### 9.2 재화 체계

런에서 쓰는 재화와 납골당에서 쓰는 재화를 분리한다. 섞이면 한쪽이 다른 쪽을 무의미하게 만든다.

| 재화 | 획득처 | 용도 |
|---|---|---|
| **시체 조각(Scrap)** | 파츠 해체, 런 중 잡템 | 모든 시설의 기본 투입물 |
| **부패 진액(Ichor)** | 부패조에서 방치 산출 | 접합로 크래프팅 촉매 |
| **골분(Bone Meal)** | 사역 골렘 파견 산출 | 파츠 강화·내구도 회복 아이템 제작 |
| **영혼재(Soul Ash)** | 런 종료 시 정산 | 납골당 시설 건설·확장, 영구 해금 |

- 앞의 셋은 **방치로 벌린다.** 영혼재만은 **반드시 런을 뛰어야** 얻는다. → 방치만으로는 진행이 막히고, 전투 루프로 되돌아오게 된다.

### 9.3 시설

납골당은 6개 시설로 구성된다. 초기에는 해체대와 부패조만 열려 있고, 나머지는 영혼재로 건설한다.

#### ① 해체대 (Dissection Table) — 변환
파츠를 재료로 분해한다. 즉시 처리되지 않고 **시간이 걸린다.**

| 파츠 등급 | 소요 시간 | 산출 |
|---|---|---|
| 일반 | 10분 | 시체 조각 3~5 |
| 희귀 | 30분 | 시체 조각 8~12 + 부패 진액 1 |
| 유니크/보스 | 2시간 | 시체 조각 20 + 진액 3 + 골분 2 |

- 동시 처리 슬롯 1개로 시작 → 확장으로 최대 4개.
- 모디파이어가 붙은 파츠를 분해하면 해당 모디파이어의 **표본**이 낮은 확률로 나온다(접합로에서 사용).

#### ② 부패조 (Rot Vat) — 순수 방치 생산
시체 조각을 통에 넣어두면 시간에 비례해 부패 진액이 고인다. 이 게임의 가장 순수한 방치 요소.

```
산출량 = floor( 투입량 × 부패조레벨 × 경과시간(시) × 0.25 )
저장 상한 = 부패조레벨 × 50        ← 상한 도달 시 생산 정지
```
- **상한이 존재하는 것이 핵심.** 상한이 없으면 오래 방치할수록 유리해져 접속 동기가 사라진다. 상한에 닿으면 멈추므로, 플레이어는 "비우러 돌아올" 이유가 생긴다.
- 레벨업은 영혼재로. 레벨이 오르면 산출량과 상한이 함께 오른다.

#### ③ 접합로 (Suture Forge) — 조합 크래프팅
파츠 여러 개를 넣고 시간을 들여 **새 파츠 하나**를 만든다. 사용자가 요청한 "조합해두면 일정 시간 뒤 완성" 기능이 여기다.

| 레시피 유형 | 투입 | 시간 | 결과 |
|---|---|---|---|
| 융합 | 동일 슬롯 파츠 2개 + 진액 3 | 45분 | 두 파츠의 스탯 평균 +15%, 스킬은 각각에서 1개씩 계승 |
| 이식 | 파츠 1개 + 모디파이어 표본 1 | 20분 | 지정 모디파이어를 파츠에 부여 |
| 정제 | 파츠 1개 + 골분 5 | 1시간 | 내구도 상한 +2, 스탯 +10% |
| 소생 | 소실된 파츠 기록 + 진액 10 + 골분 8 | 4시간 | 런에서 잃은 파츠를 복원 |
| 정착 | 날것 파츠 + 조각 8 + 진액 1 | 20분 | 날것 표식을 지운다 (§3.4) |
| 수복 | 손상된 파츠 + 조각 12 + 골분 2 | 30분 | 내구도를 상한까지 회복. 부패한 것도 되살린다 |

- **융합이 접합로의 주역.** "화염 팔의 스킬 + 고공격력 팔의 스탯"을 한 파츠로 합치는 것이 가능해지면서, 런 중에 아쉽게 버린 파츠에 두 번째 생명이 생긴다.
- **두 칸에서 시작한다.** 정착은 전투 드랍이 반드시 거쳐야 하는 길이라 한 칸이면 병목이 된다.
  제단에서 4칸까지 늘린다.
- 칸이 찼을 때 **버튼이 그냥 흐려지기만 하면 고장으로 읽힌다.** 못 누르는 이유를 버튼에 적는다
  (`접합로가 꽉 참 (2/2칸)`, `정착할 날것이 없다`, `재료가 모자라다`).
- 완성품은 **표본실로 들어가며**, 다음 런의 시작 장비 후보가 된다. 진행 중인 런에 즉시 투입되지는 않는다(런 내 난이도 곡선을 보호).
- 동시 작업 슬롯 1개로 시작 → 최대 3개.

#### ④ 사역 골렘 안치소 (Labor Golem Bay) — 파견 방치
런에서 쓰던 골렘 구성을 **사역 골렘**으로 등록해 파견 보낸다. 사용자가 말한 "만들어놓은 골렘으로 자원을 만든다"가 여기다.

- 등록 슬롯: 1개 시작 → 최대 3개. 등록된 골렘의 파츠는 **런에서 사용할 수 없다.** (강한 파츠를 노동에 쓸지, 전투에 남길지의 선택)
- 파견지는 3~4곳, 각각 요구 스탯과 산출물이 다르다.

| 파견지 | 요구 | 산출(시간당) | 위험 |
|---|---|---|---|
| 공동묘지 | 없음 | 골분 4 | 없음 |
| 무너진 갱도 | atk 25+ | 골분 6 + 시체 조각 10 | 내구도 6시간당 -1 |
| 역병 늪지 | def 30+ 또는 부패 방어속성 | 진액 8 | 내구도 4시간당 -1 |
| 전장 유적 | spd 30+ | 랜덤 파츠 (6시간당 1개) | 내구도 3시간당 -1 |

```
산출량 = 파견지기본 × (1 + 관련스탯/100) × 경과시간(시)
```
- **파견은 내구도를 갉아먹는다.** 방치 수익과 파츠 수명이 정면으로 교환된다 — §3.3의 소실 압박이 거점에서도 이어진다.
- 내구도가 0이 되면 파견 중에도 파츠가 소실되고 골렘 등록이 해제된다. 파견 설정 화면에서 "이 파츠는 N시간 후 소실됩니다" 경고를 반드시 표시.

#### ④-B 작업반 (Work Crew) — 골렘을 일에 붙인다
부속을 작업반에 세워 두면 **해체대와 접합로의 작업 시간이 줄어든다.**

```
능률 = Σ(공격 + 방어 + max(0,속도) + 집중 + 체력/20)
단축율 = min(60%, 능률 / 200)
```

- 상한 60% — 좋은 골렘을 세워도 기다림 자체를 없애지는 못한다.
- 배치한 부속은 탐험에 쓸 수 없다(사역 파견과 같은 규칙). 대신 **내구도는 닳지 않는다.**
- 전투용 골렘은 한 번에 하나뿐이지만, 남는 부속을 놀리지 않고 작업에 돌리는 길이 생긴다.

#### ④-C 정비대 (Overhaul Bench) — 방어도와 핵을 되돌린다
§5.7의 두 자원을 시간과 재료로 복구한다.

- **방어도 재건** — 모든 부위의 방어도를 상한까지. 조각 40 + 골분 4, 40분.
- **핵 안정화** — 핵 체력을 가득. 진액 5 + 골분 4, 60분.

작업반(④-B)이 배치돼 있으면 이 작업도 함께 빨라진다.

> **파츠가 머무는 자리는 일곱이다.** 소지품 · 표본실 · 조립대 · 파견 · 해체대 · 접합로 · 대장간.
> 세이브를 읽을 때 uid 번호표를 이 **전부**에 대고 맞춰야 한다(`resyncUids`).
> 세 곳을 빠뜨렸더니 거기 올려 둔 파츠의 번호를 새 파츠가 다시 쓰는 일이 생겼고,
> 같은 uid가 둘이 되자 **장착 표시가 엉뚱한 부속에 붙었다.**

#### ⑤ 표본실 (Specimen Vault) — 안전한 창고
- 파츠 보관 슬롯. 3칸 시작 → 최대 10칸.
- **여기 맡긴 것은 무슨 일이 있어도 남는다.** 그것이 이 방의 전부다.
- 소실된 파츠의 **기록**이 여기 남아 접합로의 '소생' 레시피 재료가 된다.

> **자동 반출을 없앤 이유.** 예전에는 런 시작 시 표본을 자동으로 꺼내 줬다(내구도 절반).
> 그런데 꺼내는 순간 그건 무덤에서 흘릴 수 있는 물건이 된다 —
> 안전하게 두는 것이 값어치인 방이 스스로 그 값어치를 깎고 있었다.
> 지금은 꺼내는 것도 넣는 것도 손으로 한다. '표본 지참 수' 해금도 함께 없앴다.

#### 정비대에 올린 동안에는 내려갈 수 없다
방어도 재건·핵 안정화는 **골렘을 통째로 올려놓는** 작업이다. 그동안 그 골렘으로 무덤에 내려갈 수 없다.
그러지 않으면 정비를 걸어 놓고 그 골렘으로 싸운 뒤, 돌아와서 회복까지 받는다.

급할 때를 위해 **물릴 수 있게** 해 두었다 — 쓴 재료는 돌아오지 않는다.
물릴 길이 없으면 실수로 걸어 둔 한 시간을 그대로 기다려야 한다.

#### ⑥ 제단 (The Altar) — 영구 해금
- 영혼재를 소비하는 메타 성장 창구. §8의 해금 항목이 전부 여기 붙는다.
- 납골당 시설의 건설·레벨업도 이 화면에서 수행.

### 9.4 시설 해금 순서

| 순서 | 시설 | 비용 | 해금 조건 |
|---|---|---|---|
| 초기 | 해체대, 부패조 | – | 첫 런 종료 시 |
| 1 | 표본실 | 영혼재 30 | – |
| 2 | 접합로 | 영혼재 60 | 파츠 10개 해체 |
| 3 | 제단 확장 | 영혼재 100 | Act 1 클리어 |
| 4 | 사역 골렘 안치소 | 영혼재 150 | Act 1 클리어 |

### 9.5 복귀 정산 화면

재접속 시 가장 먼저 보이는 화면. 방치형의 보상감은 **여기서 결정된다.**

```
┌───────────────────────────────────────────────┐
│  당신이 자리를 비운 사이 — 7시간 12분          │
├───────────────────────────────────────────────┤
│  부패조     부패 진액 +86        [상한 도달]   │
│  해체대     오우거의 팔 해체 완료              │

│  접합로     '융합' 완료 → 재빠른 도끼팔        │
```

- `[상한 도달]` 같은 경고를 눈에 띄게 — 다음 접속 주기를 플레이어가 스스로 조절하게 만든다.

### 9.7 설계상 지켜야 할 선

1. **방치가 전투를 대체하지 않는다.** 영혼재는 오직 런에서만 나온다. 방치는 런의 출발선을 올릴 뿐 런을 건너뛰게 하지 않는다.
2. **상한이 접속 리듬을 만든다.** 부패조 상한, 파견 산출 상한, 오프라인 상한 — 셋 다 "돌아올 이유"를 만드는 장치다.
3. **결정 없는 방치는 넣지 않는다.** 모든 시설은 최소 하나의 선택을 요구한다. 무엇을 해체할지, 어떤 파츠를 노동에 바칠지, 상한 전에 돌아올지.
4. **자동 수령은 없다.** 복귀 정산 화면을 반드시 거치게 한다. 그 화면이 방치형의 보상 순간이다.

#### ④ 사역 골렘 안치소 — 자원을 주워 오게 보낸다
**조립대에서 세운 골렘**을 밖으로 내보낸다. 작업반과 같은 원칙이다 — 부속 낱개로는 아무 일도 안 된다.

| 터 | 요구 | 시간당 산출 | 부속 줍기 | 내구도 |
|---|---|---|---|---|
| 공동묘지 | 없음 | 골분 2 | 8시간마다 25% | 닳지 않음 |
| 무너진 갱도 | 공격 25 | 골분 3 · 조각 5 | 7시간마다 35% | 6시간마다 1 |
| 역병 늪지 | 방어 30 | 진액 4 | 9시간마다 30% | 4시간마다 1 |
| 전장 유적 | 속도 30 | 조각 3 | 5시간마다 **55%** | 3시간마다 1 |

- 산출은 골렘의 **요구 능력치에 비례해** 늘어난다 (`1 + 능력치/100`).
- 주워 온 부속은 **표본실**로 들어가고, **날것**이라 정착을 거쳐야 쓴다.
  표본실이 차면 소지품으로 넘어가며 그 사실을 알려 준다.
- 내구도가 닳고, 부속이 다 삭으면 파견이 저절로 끝난다. **공짜 수익은 없다.**

48시간 실측: 공동묘지 골분 123·부속 2(무손상) / 갱도 조각 309+골분 185·부속 2 /
유적 조각 144·**부속 6**이지만 내구도 6→1~3. 안전과 수확을 맞바꾸는 자리가 된다.

한 골렘은 작업반과 파견 중 **한쪽에만** 설 수 있고, 나가 있는 동안에는 해체할 수 없다.

### 9.6 조립대와 작업반 — 일을 하는 것은 골렘이다

**핵은 여분이 있어야 한다.** 지금 전투 골렘에 박혀 있는 핵은 뽑아 쓸 수 없다 —
그건 당신이 탈 몸이다. 상점에서 사거나 단계를 끝내면 여분이 들어온다.

**핵의 체력은 핵마다 따로 기억한다.** 새로 산 핵은 온전한 채로 들어오고, 빼 둔 핵은 깎인 만큼을 그대로 안고 나간다.
즉 **핵을 갈아 끼우는 것 자체가 회복 수단**이며, 반쯤 깎인 핵은 정비대(§9)에서 고치거나 새 핵을 사거나 둘 중 하나다.

**부속은 직접 고른다.** 처음엔 슬롯별로 가장 능률 좋은 것을 자동으로 밀어 넣었는데,
그러면 아껴 두려던 부속까지 빨려 들어간다. 이제 핵만 올려 빈 골렘을 세운 뒤
자리마다 무엇을 붙일지 고른다.


**부속을 세워 두는 것으로는 아무 일도 일어나지 않는다.** 손을 놀릴 몸이 있어야 한다.

- **조립대** — 여분 핵 하나에 사역 골렘 한 기를 세운다. 슬롯별로 가장 능률이 좋은 여분 부속을
  자동으로 붙인다(다섯 칸을 손으로 채우게 하지 않는다). 해체하면 핵과 부속이 전부 돌아온다.
- **작업반** — 세워 둔 골렘을 붙이면 해체대·접합로 작업 시간이 줄어든다.
  능률 = `핵 체력 ÷ 10 + 부속 능력치 합`, 단축 상한 60%.
- 핵을 여러 개 모으면 골렘을 여러 기 세울 수 있다. 핵이 전투용 한 자리가 아니라
  **거점 운영의 자원**이 되는 지점이다.

> 예전에는 부속을 낱개로 작업반에 세웠다. 개념이 맞지 않을 뿐 아니라,
> 핵을 모을 이유도 사라진다. 구 세이브에서 세워 뒀던 부속은 마이그레이션에서 소지품으로 돌려준다.

## 10. 마을 「시체골(Corpsehollow)」

납골당(§9)이 네크로맨서의 **개인 작업장**이라면, 시체골은 그 작업장이 서 있는 **마을**이다.
산 자와 죽은 자가 적당히 뒤섞여 사는 변두리 마을. 아무도 네크로맨서에게 무엇을 하냐고 묻지 않는다.

마을은 런과 런 사이에 들르는 공간이며, 여기서 하는 일은 셋이다 — **목표를 받고(의뢰소), 장비를 갖추고(상점·대장간), 네크로맨서 자신을 강화한다(조합).**

### 10.1 마을과 납골당의 역할 분리

| | 납골당 (§9) | 마을 (§10) |
|---|---|---|
| 성격 | 시간을 들여 기다리는 곳 | 재화를 써서 즉시 얻는 곳 |
| 자원 | 시체 조각·진액·골분 (방치 산출) | 은화(Silver)·영혼재 |
| 결정 | 무엇을 얼마나 오래 돌릴까 | 지금 무엇을 살까 |

#### 재화 다섯 가지

| 재화 | 성격 | 얻는 곳 | 쓰는 곳 |
|---|---|---|---|
| **은화** | 마을 재화 | 전투 후 시체 · 파츠 판매 · 의뢰 | 상점 · 대장간 제작과 강화 · 속성 도가니 |
| **영혼재** | 메타 재화 | 탐험 종료 정산 · 의뢰 | 제단의 영구 해금 · 술법 습득 |
| **시체 조각** | 기본 재료 | 유해 더미 · 해체대 · 파견 | 정착 · 이식 · 수복 · 부패조 · 방어도 수리 · 제작 |
| **부패 진액** | 촉매 | 부패조 · 희귀 이상 해체 · 늪지 파견 | 정착 · 융합 · 이식 · 소생 · 핵 안정화 |
| **골분** | 정밀 재료 | 파견 · 유해 더미 · 유니크 해체 | 정제 · 소생 · 수복 · 정비대 · 강화 |

게임 안에서는 **뼈 수습꾼(§10.2-B)의 「재화가 뭔지 알려달라」** 와 소지품 화면에서
같은 내용을 언제든 다시 볼 수 있다. 재화가 다섯이나 되면 어디에 쓰는지 잊기 쉬우므로,
설명을 한 번 흘려보내지 않고 **상시 열람 가능한 자리**에 둔다.

**재화가 분리되어 있는 것이 핵심이다.** 방치로 번 재료는 마을에서 쓸 수 없고, 마을 재화인 **은화**는 던전에서 주워오거나 전리품을 팔아야 생긴다. 두 축이 서로를 대체하지 못한다.

### 10.2 의뢰소 (The Requisition)

무작위 의뢰 **3건**이 상시 게시된다. 셋을 **모두 완료하면** 새 3건이 갱신된다.

- 하나씩 갱신되지 않고 **세트 단위로 갱신되는** 것이 중요하다. 쉬운 것만 골라 먹지 못하게 하고, 마지막 하나가 까다로우면 "저걸 해치워야 다음 판이 열린다"는 압박이 생긴다.
- **리셋** — 재화를 지불하고 3건을 통째로 새로 뽑는다. 비용은 **누적 증가**(50 → 100 → 200 은화)하며 세트를 완료하면 초기화된다. 도저히 못 할 의뢰를 만났을 때의 탈출구이되, 남발하면 비싸진다.

#### 의뢰 유형

| 유형 | 예시 | 판정 |
|---|---|---|
| 처치 | 뼈사냥개 5체 처치 | 런 중 누적 |
| 수집 | 부패 속성 파츠 3개 반납 | 소지품에서 차감 |
| 도달 | 한 런에서 3층 보스 격파 | 단일 런 내 달성 |
| 제약 | 파츠를 하나도 잃지 않고 2층 클리어 | 단일 런 내 달성 |
| 처분 | 내구도 0 직전 파츠 2개 해체 | 즉시 |

- **제약형 의뢰가 의뢰소의 주역이다.** 평소와 다른 방식으로 플레이하게 만들어, 정해진 최적 루트를 흔든다.
- 보상: 은화 + 영혼재 + 낮은 확률로 파츠·도면.
- 진행도는 마을에 돌아오지 않아도 런 중에 갱신되며, 완료 알림은 전투 로그에 끼어든다.

### 10.2-B 뼈 수습꾼 바르그 (구제 · 안내 NPC)

무덤에서 돌아오지 못한 자들의 부속을 주워다 파는 노인. 두 가지 역할을 한다.

1. **안전망** — **모자란 것만** 채워 준다.
   - 핵이 없으면 → 주워 맞춘 핵
   - 소지 부속이 §3.6의 최소치(2개) 이하면 → 최하급 부속을 3개까지
   - 빈 슬롯이 있으면 남는 부속을 알아서 끼워 준다

   횟수 제한은 두지 않는다 — 진행이 막히는 상태를 만들지 않는 것이 이 NPC의 존재 이유다.
   다만 부속이 3개 이상 남아 있으면 도움을 주지 않는다. 구제는 바닥을 쳤을 때만이다.
2. **안내** — 주제별로 나뉜 상시 열람 창구다.
   - **재화가 뭔지 알려달라** — 재화 다섯 가지의 출처와 용도(§10.1). 소지품 화면에서도 같은 것을 연다.
   - **부위 조준이 뭐냐** — 조준 세 가지의 수치, 부위를 부수는 것과 부속을 얻는 것의 교환, 그리고 내 쪽의 핵·방어도 구조(§5.7).
   - **날것 부속이 뭐냐** — 날것과 정착의 차이, 정착 경로(§3.4).
   - **조언을 듣는다** — 그 밖의 짧은 규칙들.

#### 처음 마주칠 때 한 번 (§16.5)
설명을 찾아 들어가지 않아도 되도록, 규칙을 **처음 만나는 순간에 한 번만** 자동으로 띄운다.

| 시점 | 내용 | 플래그 |
|---|---|---|
| 첫 전투 | 방어도가 핵보다 먼저 닳는다 · 조준의 교환 | `log.hintAim` |
| 첫 날것 획득 | 날것의 대가와 정착 경로 | `log.hintRaw` |

두 번째부터는 짧은 한 줄로 대체한다. 같은 설명을 반복하면 로그가 묻힌다.

> 앞으로 튜토리얼을 담당할 자리다. 첫 런의 안내, 시스템 해금 시점의 설명이 여기 붙는다.

### 10.3 상점 「썩은 손수레」

소모품과 파츠를 은화로 사고팔 수 있다. 재고는 마을 방문마다 갱신된다.

| 품목 | 예시 | 효과 |
|---|---|---|
| 물약 | 시체 기름 | 전투 중 골렘 HP 30% 회복 |
| 물약 | 역청 한 병 | 파츠 1개 내구도 +3 (마을·던전 어디서나) |
| 스크롤 | 해체의 문양 | 전투 중 1회, 적 방어 랭크 -2 |
| 스크롤 | 귀환의 문양 | 던전에서 즉시 마을로 (전리품 유지) |
| 파츠 | 매물 파츠 2~3개 | 무작위 슬롯·모디파이어 |
| 판매 | — | 소지한 파츠·잡템을 은화로 환전 |

#### 10.3-B 보급품 (시간 충전)

기본 재료 셋은 수레가 늘 조금씩 받아 둔다. **시간이 지나면 한 개씩 차오르고, 칸이 차면 더는 쌓이지 않는다.**
은화로 시간을 사되 무한히는 못 사게 하려는 장치다 — 방치 시설(§9)의 산출을 급할 때 앞당기는 용도이지, 대체가 아니다.

| 보급품 | 값 | 최대 재고 | 충전 간격 |
|---|---|---|---|
| 시체 조각 | 은화 9 | 40 | 3분 |
| 골분 | 은화 45 | 12 | 12분 |
| 부패 진액 | 은화 70 | 8 | 20분 |

- 재고는 세이브(`town.supply`)에 `{ n, at }`으로 남고, 상점에 들어설 때 지난 시간만큼 한 번에 계산한다(§9의 정산과 같은 방식).
- 가득 찬 칸에서 하나를 빼면 그 순간부터 다시 충전이 시작된다. 남은 자투리 시간은 버리지 않는다.

**판매 기능이 은화의 주 공급원이다.** 던전에서 주운 파츠 중 빌드에 안 맞는 것을 팔아 현금화하는 것이 정상적인 순환이다. 이 때문에 "쓸모없는 드랍"이 완전한 낭비가 되지 않는다.

### 10.4 대장간 「뼈 모루」

납골당의 접합로(§9.3-③)가 **파츠끼리 합치는 곳**이라면, 대장간은 **골렘에 맞춰 장비를 제작하는 곳**이다.

- 제작에는 **도면(Schematic)** 과 재료, 은화가 필요하다. 도면은 의뢰 보상·상점·보스 드랍으로 얻는다.
- 제작물은 파츠 슬롯을 쓰지 않는 **부착물(Attachment)** 이다. 골렘당 2칸.

| 부착물 | 재료 | 효과 |
|---|---|---|
| 철제 이음쇠 | 시체 조각 20 + 은화 120 | 모든 파츠 내구도 소모가 2전투당 1회 |
| 균형추 | 골분 8 + 은화 90 | 속도 +6, 회피 +4 |
| 방혈관 | 진액 6 + 은화 150 | 피해를 줄 때마다 HP 3 회복 |
| 속성 도가니 | 도면 필요 | 지정한 팔 스킬 1개의 속성을 변경 |

#### 파츠 강화
부속 하나를 맡기면 **모든 능력치 +8%**, 최대 +3단계. 은화와 재료를 내고 시간을 기다린다.

| 단계 | 비용 | 시간 |
|---|---|---|
| +1 | 은화 120 · 조각 10 · 골분 2 | 25분 |
| +2 | 은화 210 · 조각 18 · 골분 4 | 45분 |
| +3 | 은화 300 · 조각 26 · 골분 6 | 65분 |

맡긴 부속은 완성될 때까지 쓸 수 없고, 완성품은 납골당 복귀 정산에 함께 나온다.

**속성 도가니가 대장간의 핵심 물건이다.** §5.3의 속성 커버리지 문제를 플레이어가 **직접 해결할 수 있는 유일한 수단**이다. 부패 몬스터에 막혔을 때, 운에 맡기지 않고 참격 스킬 하나를 화염으로 바꿔 돌파할 수 있다.

### 10.5 강령술사 조합 (The Conclave) — 네크로맨서 스킬

**골렘이 아니라 네크로맨서 본인이 배우는 스킬**을 판다. 골렘 스킬은 파츠에서 나오고 런마다 갈리지만, 네크로맨서 스킬은 **영구적이며 모든 런에 따라온다.**

자원은 **영력(Will)** 이다. 전투 시작 시 3, 매 턴 +1, 상한 10. 골렘의 스킬 충전과 별개의 자원이라 "골렘 커맨드 + 네크로맨서 개입"이 매 턴 두 겹으로 겹친다.

#### 10.5-A 술법은 골렘의 공격과 **함께** 나간다

전에는 술법이 골렘의 턴을 빼앗았다 — 술법을 쓰면 그 턴 골렘은 때리지 못했다.
그러면 술법은 사실상 "때리기를 포기하는 값"이 되고, 계산해 보면 대부분의 경우 그냥 때리는 쪽이 낫다.
배워 봐야 안 쓰는 계열이 되고, 이 게임의 그림 —
**네크로맨서가 뒤에서 술법을 걸고 골렘이 앞에서 때린다** — 도 화면에 나타나지 않는다.

그래서 술법은 **골렘의 공격에 얹어 나가는 것**이 됐다.

- 커맨드 목록 위의 `🕯 술법` 토글로 **미리 걸어 둔다.** 눌러 돌리면 쓸 수 있는 술법을 차례로 고르고, 한 바퀴 돌면 「없음」이다.
- 그 상태로 골렘의 기술을 고르면 **같은 턴에 술법 → 골렘 → 적** 순서로 터진다.
- 술법을 안 걸어도 골렘은 그냥 공격한다. **거는 쪽이 선택이지 기본이 아니다.**
- 값은 여전히 **영력과 재사용 대기**가 받는다. 턴을 안 먹을 뿐 매 턴 쓸 수는 없다.
- 물약과 관찰은 그대로 골렘의 턴을 대신한다 — 그쪽은 "때리기를 포기한다"가 곧 비용이다.

시뮬레이터는 술법을 쓰지 않으므로(§16.3) 단계 밸런스는 **술법 없이도 되는 하한**으로 남는다.
술법은 그 위에 얹는 여유다.

#### 세 계열

| 계열 | 성격 | 예시 |
|---|---|---|
| **보조** | 골렘을 직접 돕는다 | 뼈 붙이기(HP 회복) · 각성(공격 랭크 +2) · 정화(디버프 1개 제거) |
| **공격** | 네크로맨서가 직접 때린다 | 영혼 창(신성 피해) · 부패의 손길(중독 부여) · 죽음의 선고(적 최대HP 비례 피해) |
| **소환** | 임시 아군을 만든다 | 해골 병사 · 시체 까마귀 · 뼈 방패 |

#### 소환 규칙

소환수는 **턴 제한이 있는 임시 아군**이다. 전투에 두 번째 행동 주체가 생긴다.

| 소환수 | 영력 | 지속 | 행동 |
|---|---|---|---|
| 해골 병사 | 4 | 3턴 | 매 턴 참격 피해. 골렘보다 먼저 행동 |
| 시체 까마귀 | 3 | 2턴 | 매 턴 적 회피 랭크 -1, 소량 피해 |
| 뼈 방패 | 3 | 2턴 | 골렘이 받는 피해를 1회 대신 받는다 |
| 역병 시체 | 5 | 1턴 | 즉시 폭발, 광역 중독 5 |

- 동시 소환 상한 **1체**. 새로 소환하면 기존 소환수는 사라진다. → "지금 무엇을 부를까"가 결정이 된다.
- 소환수는 전투 종료 시 사라지며, 내구도를 소모하지 않는다. **파츠를 아끼며 싸우는 수단**이기도 하다.
- 소환수가 있으면 적의 공격이 일정 확률로 소환수에게 간다(어그로 분산).

#### 습득 구조

- 스킬 하나당 영혼재로 구매, 이후 은화로 **3단계까지 강화**.
- 동시 장착 슬롯 **3개**. 배운 스킬이 늘어도 한 런에 셋만 들고 간다 → 런마다 다른 조합.
- 슬롯 확장은 제단(§9.3-⑥)의 영구 해금 항목.

## 12. 화면 구성 — 2분할 레이아웃

### 12.1 기본 원칙

화면을 **세 영역**으로 나눈다. 왼쪽은 *지금 어디에 있고 무엇을 가지고 있는가*(상태),
오른쪽은 *무슨 일이 벌어졌는가*(순수 텍스트 로그), 그리고 **하단 전체 폭이 선택지**다.

```
┌──────────────────────────┬──────────────────────────┐
│                          │  로그 (순수 텍스트)       │
│        상태 패널          │  > 골렘이 발톱팔을 휘두른다│
│   (맵 · 마을 · 골렘)      │  > 상단을 노린다.         │
│                          │  > 효과가 굉장했다!       │
├──────────────────────────┴──────────────────────────┤
│  선택지 — 좌우 구분 없이 화면 폭 전체를 쓴다          │
│  [🎯 조준 상단] [1] 발톱 후려치기  [2] 강철 방벽 …   │
└─────────────────────────────────────────────────────┘
```

선택지를 오른쪽 아래에 두면 폭이 절반으로 묶여 버튼이 두세 개씩만 들어간다.
하단 전체 폭으로 빼면 같은 높이에 배가 들어가고, 오른쪽은 텍스트만 남아 읽기에 전념할 수 있다.

**왼쪽은 상황에 따라 내용만 바뀌고 자리는 고정된다.** 이 일관성이 텍스트 게임의 방향 감각을 만든다.

| 상황 | 왼쪽 패널 |
|---|---|
| 던전 탐험 | 층 미니맵 · 현재 위치 · 미방문 방 |
| 전투 | 적과 골렘을 **좌우로 나란히** + 부위 도식 |
| 마을 | 건물 타일 9칸 — 눌러 들어간다 |
| 골렘 상태창 | 핵 체력 · 부위 도식 · (접힘) 능력치 · 스킬 · 부착물 |
| 납골당 | 시설 타일 — 각 칸에 진행 중인 작업과 남은 시간 |

오른쪽은 어느 상황에서나 **로그(위) + 선택지(아래)** 구조를 유지한다. 로그는 누적 스크롤, 선택지는 항상 하단 고정.

#### 12.1-A 하단 독은 높이가 고정된다

선택지 개수만큼 하단이 늘었다 줄었다 하면 화면이 매번 다르게 보이고, 로그와 선택지의 경계가 흔들린다.
그래서 하단은 **칸 크기가 같은 격자**로 고정한다.

- 버튼 높이는 모든 화면에서 같다(`--btn-h`). 이름 한 줄, 곁말 한 줄 — 글자 수가 달라도 칸은 같다.
- 독의 높이는 줄 수로 정해진다(`--dock-rows`: 기본 3, 세로 4, 가로 저해상도 3). 넘치면 **독 안에서 스크롤**한다.
- 긴 목록은 여전히 쪽 나누기(`paged: true`)로 자른다. 독이 커지는 일은 없다.

#### 12.1-A' 고정된 독이 만든 문제와 그 처리

높이를 고정하고 나니 **폭과 높이가 남는데도 글자가 잘리는** 일이 생겼다. 원인은 셋이었다.

| 증상 | 원인 | 처리 |
|---|---|---|
| 버튼이 넷뿐인데 이름이 잘린다 | `auto-fill`이 빈 열 여섯 개를 만들어 버튼이 156px에 묶였다 | **`auto-fit`** — 빈 열을 접어 남은 버튼이 넓어진다 |
| 독 아래가 늘 비어 있다 | 164px 중 **102px(62%)** 이 빈 채로 버려졌다 | 줄 수에 맞춰 **줄 높이를 늘려 채운다** (기본의 2배까지) |
| 숫자 배지가 이름을 밀어낸다 | 배지가 오른쪽 위에 얹혀 첫 줄의 폭을 먹었다 | 배지는 왼쪽 위로, 이름은 **`text-indent`로 첫 줄만** 비켜 간다 |

이름을 몇 줄까지 풀지는 **칸의 높이가 정한다**(`--nm-lines`). 무조건 두 줄로 두면
칸이 낮을 때 곁말이 칸 밖으로 밀려 잘려 나간다 — 읽으라고 푼 것이 오히려 못 읽게 만든다.

독이 넘치면 그림자로 알린다. 높이가 고정이라 넘친 줄은 **소리 없이** 가려지기 때문이다.

#### 12.1-A'' 쪽 나누기는 저절로 된다

숫자 키는 **1~9뿐**이고 독은 높이가 고정이다. 항목이 그보다 많으면
열 번째부터는 키가 없고, 넘친 줄은 스크롤 뒤로 숨는다
(실측: 상점에서 6개가 키를 못 받고 독이 116px 넘쳤다).

그래서 **아홉을 넘거나 독에 안 들어가면 저절로 쪽을 나눈다.** 한 쪽의 크기는
`min(숫자 키가 닿는 수, 독에 실제로 들어가는 칸 수)`로 정한다 —
칸 수는 그리기 전에 **독의 폭과 높이에서 계산**한다(`dockCapacity`).

- 쪽 넘김은 버튼 셋이 아니라 **한 줄짜리 띠**다. 버튼 셋이면 칸을 셋 먹는다.
- 그래서 칸 계산에서 띠는 **한 줄을 통째로** 뺀다.
- `paged: false`로 끌 수 있다. 마을 같은 허브는 항목이 다 보여야 한다(지금은 넷뿐이라 걸리지 않는다).

<b>같은 함정을 또 밟았다.</b> 세로모드 변수(`--dock-rows:4`)를 미디어 쿼리에 뒀는데,
그 블록이 파일 **앞쪽**에 있어 뒤의 기본 `#app` 선언에 지고 있었다.
명시도가 같으면 나중에 선언된 쪽이 이긴다 — §12.2에서 한 번 적어 둔 것을 그대로 반복했다.
선택자를 `#app#app`으로 올려 고쳤다.

#### 12.1-C 잘린 것은 쪽지로 펼친다

버튼 폭에는 한계가 있다. 「썩어가는 무덤파괴자의 쇠망치팔」은 어떻게 해도 한 줄에 안 들어간다.
그래서 **자르되, 펼쳐 볼 수단을 같이 둔다.**

| 입력 | 동작 |
|---|---|
| 마우스를 올린다 | 쪽지가 뜬다. 누르는 것은 그대로 **한 번**이다 |
| 손가락으로 한 번 누른다 | 쪽지가 뜨고 그 버튼이 「고름」 상태가 된다 — **실행되지 않는다** |
| 같은 것을 한 번 더 누른다 | 그때 실행된다 |

- **더 보여 줄 것이 없는 버튼은 예전처럼 한 번에 눌린다.** 잘린 글자도 `info`도 없으면 두 번 누를 이유가 없다.
- 못 누르는 버튼도 눌러서 쪽지를 볼 수 있다. 이유(`조각 7 모자라다`)가 잘렸을 때 그것을 읽을 유일한 길이다.
- 부속 목록은 `info: UI.partTip(part)`로 **등급·자리·내구도·요구 마력·능력치·기술·이상**까지 한 장에 펼친다.
  쪽지가 없으면 버튼에 있던 이름과 곁말을 잘리지 않게 그대로 보여 준다.

#### 12.1-B 요약하고 감춘다

왼쪽 패널이 한 번에 쏟아내는 정보가 너무 많으면 아무것도 안 읽힌다. 세 가지 규칙을 둔다.

1. **숫자 여섯 줄보다 그림 하나** — 부위 상태는 사람 모양 도식(`.bodymap`)으로 세우고 **퍼센트 하나씩만** 보여 준다.
   끼운 부속·기술·내구도는 **누르면** 아래에 펼친다. 전투·정비·탐험이 같은 그림을 쓰므로 읽는 법이 하나다.
2. **늘 볼 것만 펼쳐 둔다** — 능력치표·스킬 목록·부착물은 접이식 구역(`<details class="sec">`)에 넣고 제목만 남긴다.
   접힌 채로도 요약 한 줄(`공격 6 · 방어 6 · 속도 22`)은 보인다. 무엇을 펼쳐 뒀는지는 화면을 다시 그려도 기억한다.
3. **들어갈 곳은 그림에서 누른다** — 마을과 납골당의 건물·시설은 선택지가 아니라 **왼쪽 타일**이다(아이콘·이름·한 줄 상태).
   숫자 키도 그대로 먹는다. 하단에는 *지금 할 행동*만 남는다 — 마을이면 「무덤으로 내려간다」·상성표·저장·기록 보관 넷.

### 12.2 가로·세로 대응

**둘 다 지원한다.** 화면 비율로 자동 전환하며, CSS만으로 처리되므로 추가 비용이 거의 없다.

```css
/* 가로 — 좌우 2분할 */
.app { display: grid; grid-template-columns: 1fr 1fr; }

/* 세로 — 위아래로 쌓기 */
@media (max-aspect-ratio: 4/5) {
  .app { grid-template-columns: 1fr; grid-template-rows: auto 1fr; }
}
```

- 전환 기준은 **화면 비율**(`aspect-ratio`)이며, 너비 560px 이하일 때도 함께 쌓는다.

#### 방어도는 목록이 아니라 도식으로
부위가 여섯이 되면서 방어도를 여섯 줄로 늘어놓으니 **화면 절반을 먹고도 한눈에 안 들어왔다.**
사람 모양으로 세워 놓고 **숫자만** 보여 준다.

```
        [머리]
 [좌완] [몸통] [우완]
 [좌각]        [우각]
```

- 각 칸은 남은 방어도 **비율(%)** 하나만 적고, 칸 안쪽이 그만큼 차오른다 — 숫자를 안 읽어도 읽힌다.
- 색이 상태를 말한다: 70% 위는 기본, 그 아래는 금빛, 35% 아래는 붉게, 무너지면 `✕`.
- **끼운 부속은 눌렀을 때만** 아래에 펼친다 (이름·등급·방어도·내구도·기술).
  펼친 자리는 턴이 바뀌어도 유지되고, 전투가 바뀌면 접힌다.
- 높이 78px. 예전 목록은 그 세 배였다.

#### 지도에서 방 상태를 구분한다
이동을 십자키로 옮기면서 "갔던 방인지"를 알 길이 지도뿐이 됐다. 네 가지를 눈으로 가른다.

| 상태 | 표시 |
|---|---|
| 지금 자리 | 방 아이콘 + 강조 테두리·배경 |
| 아직 안 가 봄 | `?` 초록 점선 — **갈 곳이 남았다는 신호라 가장 눈에 띈다** |
| 가 봤지만 안 끝남 | 방 아이콘 + 밝은 실선 |
| 끝난 방 | 방 아이콘, 흐리게 물러난다 |

범례는 한 줄로 두고, 안 가 본 방이 몇 개 남았는지 숫자로 붙인다.

#### 이동은 십자키가 맡는다
화면 오른쪽 아래에 붙박이 십자키를 둔다. **선택지에는 방향을 넣지 않는다.**

- 같은 것이 두 벌이 되면 화면만 좁아진다. 실제로 선택지의 마지막 항목(상성표)이
  십자키에 가려 누를 수 없는 상태였다.
- 십자키가 떠 있는 동안 `#app.dpad-on`이 붙어 **선택지 오른쪽에 그만큼 자리를 비운다.**
  겹치면 덮인 선택지를 아예 못 누른다 — 안 보이는 게 아니라 못 누르는 것이 문제다.
- 선택지에서 뺀 정보(미탐험 / 방 종류)는 버튼 자체가 지닌다.
  아직 가 보지 않은 방향은 강조색으로 뜨고, 자세한 것은 `title`에 남긴다.
- 방향키(키보드)도 그대로 동작한다. 십자키와 같은 표를 읽는다.

#### 목록이 길어지는 화면 — 쪽 나누기
선택지 상자는 원래 스크롤된다(`max-height` + `overflow-y`). 그런데 화면 코드가
`spare.slice(0, 7)`처럼 **앞에서 잘라 넘기고 있어서**, 정착 대기 9개 중 7개까지만 보이고
나머지는 볼 방법이 없었다. 자르기를 전부 걷어냈다.

그 위에 **쪽 나누기**를 얹었다 — 다만 **`{ paged: true }`를 준 화면에서만** 켠다.

- 항목이 7개를 넘으면 `◂ 이전 / n / m쪽 / 다음 ▸`이 붙는다.
- `pin: true`인 선택지(돌아간다, 작업반에 붙인다 같은 것)는 **모든 쪽에 남는다.**
  이게 없으면 자리가 여섯인 사역 골렘 화면에서 '해체'가 둘째 쪽으로 밀려난다.
- 마을처럼 항목이 다 보여야 하는 허브는 켜지 않는다. 상자가 알아서 스크롤한다.

> 처음엔 모든 화면에 자동으로 켰다가 **마을 메뉴의 '소지품'이 둘째 쪽으로 밀려났다.**
> 전역 동작을 바꿀 때는 그 동작이 필요 없는 화면까지 같이 바뀐다.

#### 모바일에서 반드시 지켜야 할 세 가지
실제 기기(갤럭시 폴드, 크롬)에서 글자가 화면을 뒤덮어 진행이 불가능했던 문제의 원인과 대책이다.

1. **`text-size-adjust: 100%`** — 안드로이드 크롬은 "모바일 최적화가 안 된 페이지"로 판단하면 글자를 임의로 확대한다(text boosting). 이걸 끄지 않으면 어떤 CSS를 써도 무너진다.
2. **`rem`의 기준을 뷰포트에 고정** — `html { font-size: calc(clamp(12px, 2.6vmin, 16px) * var(--ui-scale)) }`.
   `rem`은 루트 글꼴 크기를 따르므로, 고정하지 않으면 사용자의 브라우저 글꼴 설정에 화면 전체가 끌려간다.
3. **글자 크기 조절바** — 상단바의 `가 100%` 를 누르면 슬라이더가 열린다. 70~160%를 무단계로 조절하며
   미리보기 문장이 함께 떠서 크기를 바로 가늠할 수 있다. 값은 `localStorage`에 저장된다.
   위 두 가지로 대부분 해결되지만, 기기·설정 조합은 예측할 수 없으므로 사용자가 직접 맞출 수단을 남긴다.

   상단바는 좁은 화면에서 **재화 묶음이 통째로 둘째 줄로 내려간다.** `nowrap + overflow-x`로 두면
   글자를 키웠을 때 가로로 밀려 잘린 것처럼 보인다 — 실제로 세로모드에서 그 문제가 났다.

   > 구현 주의: 팝오버에 `#scalebox { display: grid }` 같은 **ID 선택자를 쓰면 브라우저 기본
   > `[hidden] { display: none }` 규칙을 이겨서 `hidden`이 먹지 않는다.** `#scalebox[hidden]{display:none}`을
   > 함께 적어야 한다. 실제로 이것 때문에 JS는 닫혔다고 보고하는데 화면에는 계속 떠 있는 상태가 나왔다.

가로모드 휴대폰(높이 520px 이하)에서는 별도 미디어 쿼리로 세로 여백을 걷어내고 선택지 영역 상한을 52dvh로 올린다.
좁은 화면에서는 선택지 버튼을 한 줄에 하나씩 배치해 글자가 잘리지 않게 한다.
- 세로에서는 상태 패널이 위, 로그와 선택지가 아래로 내려간다. **선택지는 세로에서도 하단 고정** — 엄지가 닿는 자리다.
- 세로일 때 상태 패널은 높이를 30dvh 이내로 제한하고, 내용이 넘치면 패널 내부에서만 스크롤한다.

#### 세로모드 로그 확보 (글자를 키워도 읽히게)
세로에서 글자를 키우면 상태 패널과 선택지가 함께 커지면서 가운데 로그가 몇 줄로 짜부라진다.
이건 글자 크기의 문제가 아니라 **세 영역이 같은 높이를 나눠 쓰는데 두 영역만 커지는** 구조의 문제다. 네 가지로 대응한다.

1. **상태 패널 접기** — 상태 패널과 로그 사이에 `상태 접기 ▲` 띠를 둔다. 누르면 `#app.panes-collapsed`가 붙어
   패널이 `max-height: 0`으로 접히고 그 높이가 전부 로그로 간다. 상태는 접었다는 사실과 함께
   `localStorage['patchwork.panesCollapsed']`에 남아 다음에도 유지된다. 가로모드에는 띠 자체가 나오지 않는다.
2. **로그 최소 높이 보장** — `grid-template-rows: minmax(0,auto) auto minmax(22dvh,1fr)`.
   위 두 영역이 아무리 커져도 로그는 화면의 22% 아래로 내려가지 않는다.
3. **세로 전용 줄 간격 압축** — `line-height: 1.42`, `gap: .12rem`. 같은 높이에 더 많은 줄이 들어간다.
4. **선택지 상한 30dvh** — 세로에서 선택지가 화면 절반을 먹지 않게 자른다(넘치면 내부 스크롤).

측정(폰 세로 기준, 로그 픽셀 높이 / 보이는 줄 수):

| 글자 크기 | 펼침 | 접음 |
|---|---|---|
| 100% | 285px (16줄) | 541px (31줄) |
| 130% | 257px (11줄) | 512px (23줄) |
| 160% | 238px (8줄) | 494px (18줄) |

> **CSS 함정 — 미디어 쿼리가 졌던 이유.** 처음엔 선택지 상한이 전혀 먹지 않았다(160%에서 389px).
> 미디어 쿼리 안의 `#choices{max-height:30dvh}`와 파일 **뒤쪽**의 기본 `#choices{max-height:46dvh}`는
> 명시도가 같아서, 미디어 쿼리 여부와 무관하게 **나중에 선언된 쪽이 이긴다.**
> 미디어 쿼리는 명시도를 올려주지 않는다. `#app #choices`처럼 한 단계 올려 적어야 한다.
> (접힘 패널의 `max-height:0`만은 인라인 상한과도 겹칠 수 있어 `!important`를 쓴다.)

## 15. 확정 사항

1. **전투 방식** — 커맨드 턴제(포켓몬형). 카드 드로우/손패/에너지 없음. 파츠가 제공하는 스킬을 매 턴 하나 선택, speed로 선후공 결정, 7속성 상성.
2. **골렘 파괴 = 즉시 런 종료.** 부활 장치 없음.
3. **내구도 0 = 파츠 소실.** 대신 네크로맨서의 도구(유물·소모품·안치실)로 소실을 방지·지연하는 것이 성장의 한 축.
4. **한국어 전용.** i18n 구조 없이 데이터에 한국어 텍스트를 직접 기입.
5. **맵은 아이작식 층 탐험.** 시드로 생성된 격자 방 구조, 되돌아가기 자유, 보스방 진입 시 층 종료. 내구도를 탐험 화폐로 전환하는 것이 채택 이유이며, 런 길이는 §6.2의 상한으로 통제한다.
6. **캠페인은 3부 9단계.** 하수도 → 공동묘지 → 미궁. 1단계 = 3층짜리 런 한 번이며 단계마다 전용 보스가 있고, 3단계 보스를 잡으면 다음 파트가 열린다. 메인 퀘스트는 뼈 수습꾼 바르그가 전담한다 (§7-A).
7. **거점 방치 콘텐츠 도입.** 납골당(The Ossuary). 서버 없이 클라이언트 타임스탬프 정산으로 구현하며, 방치는 런을 대체하지 않고 출발선만 올린다.

## 16. 구현 메모

기획과 코드가 어긋나기 쉬운 지점만 적는다.

### 16.1 접합로 산출물의 표현
융합·정제된 파츠는 원본 정의의 스탯을 쓰지 않고 **인스턴스가 자체 스탯을 들고 다닌다**
(`part.fused.stats`, `part.fused.skills`, `part.refined`). `partStats()`·`partSkills()`가 이를 우선 적용하며,
이름에는 `이어붙인`·`정제된` 접두사가 모디파이어 접두사 뒤에 붙는다.

### 16.1-B 세이브 마이그레이션 — 반드시 같이 고칠 것

`load()`는 `migrate()`를 거친다. **세이브에 새 필드를 추가하면 여기도 함께 채워야 한다.**
그러지 않으면 이미 플레이 중인 사람의 화면에서 `undefined.map` 같은 오류가 난다 —
새 기능은 새 게임에서만 검증되기 때문에 놓치기 쉽다.

실제로 골렘 핵(`save.cores`)과 작업반(`ossuary.crew`)을 추가했을 때 이 처리를 빠뜨려,
기존 세이브에서 핵 교체와 작업반 화면이 모두 터졌다.

### 16.4-A 처음부터 다시

테스트할 때 새 기록으로 시작할 방법이 없었다. 「기록 보관」에 **처음부터 다시**를 뒀다.

- 되돌릴 수 없는 일이므로 **예/아니오로 한 번 묻는다.** 무엇이 지워지는지(진행·탐험·소지·재화)를 먼저 보여 준다.
- 지우기 전의 기록은 `<SAVE_KEY>.before-reset`에 남는다. 가져오기로 되살릴 수 있다 —
  §16의 원칙대로 **되돌릴 수 없는 일은 만들지 않는다.**

### 16.5 안내를 두는 두 자리

규칙이 늘어날수록 "이게 뭐였지"가 늘어난다. 설명은 두 자리에 둔다.

1. **처음 마주칠 때 한 번** — 자동으로 뜬다. 플래그는 `save.log.hint*`에 남기고 마이그레이션에 반드시 추가한다.
2. **언제든 다시** — 뼈 수습꾼(§10.2-B). 한 번 흘려보낸 설명을 되찾을 수 있는 유일한 자리다.

새 시스템을 넣을 때 이 둘을 같이 넣지 않으면, 구현은 됐는데 아무도 모르는 기능이 된다.

#### 16.5-A 못 누르는 버튼은 이유를 말한다

버튼이 흐려지기만 하면 **고장으로 읽힌다.** 못 누르는 이유를 곁말 자리에 적는다.

- **재료가 걸린 것은 부족분을 숫자로.** "재료가 모자라다"는 무엇을 구해 와야 하는지 알려 주지 않아,
  창을 나갔다 들어오며 재화를 일일이 대조하게 만든다. `shortText()`가
  `조각 7 · 진액 1 모자라다`처럼 **모자란 것만, 모자란 만큼** 적는다.
  접합로·대장간·영혼석 강화·제단이 모두 이 함수를 쓴다.
- 짧은 이름을 쓴다(`RES_SHORT`). "시체 조각 8 모자라다"는 버튼 폭에서 잘려 못 읽는다.
- 재료 말고 다른 이유(칸이 찼다, 여분이 없다, 더는 못 올린다)도 같은 자리에 같은 방식으로 적는다.

#### 16.5-B 이름이 잘리는 목록은 확인을 거친다

부속 이름은 「독을 품은 얼어붙은 시체의 언 팔」처럼 길어서 버튼 폭에서 잘린다.
무엇인지 모른 채 되돌릴 수 없는 선택(해체·융합)을 누르게 해서는 안 된다.

- 목록 버튼의 곁말에 **자리와 내구도**를 적어 같은 이름끼리 구분되게 한다.
- 누르면 바로 실행하지 않고 `partDetailScreen(part, back, action)`으로 **상세 화면**을 띄운다 —
  왼쪽에 능력치·방어도·기술·이상까지 전부 펼치고, 아래는 「예, 해체한다」 / 「아니오」 둘뿐이다.
- 이 상세 화면은 소지품에서 쓰던 것과 **같은 화면**이다. `action`을 주면 확인 화면이 된다.

### 16.2 정산 시점
`settle()`은 세 곳에서 호출된다 — 부팅, 탐험을 마치고 마을로 돌아올 때, 납골당에 들어갈 때.
`save()`는 `lastSeenAt`을 건드리지 않는다. 건드리면 마을에 머무는 동안 시간이 흐르지 않게 된다.

### 16.3 층별 엘리트·보스
전용 엘리트가 없는 층은 일반 몬스터를 승격시켜 쓴다 (HP ×2.2, 공격 ×1.2, 방어 ×1.3, `굶주린` 접두사).
1층 엘리트=고블린 승격, 2층=살가죽 직조공, 3층=무덤파괴자 오우거. 3층 보스만 전용(무덤군주)이다.

### 16.4 한국어 조사
데이터와 코드의 텍스트는 `가(이)` `을(를)` `으로(로)` 형태로 쓰고,
`josa()`가 받침을 판별해 한 번에 교정한다. 로그·선택지·패널 모두 이 함수를 거친다.

## 17. 남은 검토 과제

- **캠페인 9단계에 파츠 풀이 따라가는지.** 단계가 올라가는데 쓸 파츠가 늘지 않으면 후반이 그대로 벽이 된다. `npm run balance`를 단계별로 확장하는 것이 선행 조건 (§7-A.7).
- 속성 상성표는 초안. 시뮬레이션으로 특정 속성 독주 여부 검증 필요.
- 스킬 상한 9개가 실제 플레이에서 과한지 확인 (7개로 낮출 여지).
- '관찰' 커맨드가 턴을 소모할 가치가 있는지 — 무료 열람으로 바꿀지 검토.
  → §7-A.4의 **각인된 파수병**(매 턴 방어 속성이 바뀐다)이 이 커맨드에 존재 이유를 주는 방향의 답이다. 3부 착수 시 함께 판단한다.
- 몸통이 방어 속성을 결정하는 구조 때문에 특정 몸통이 압도적 정답이 되지 않도록 몸통별 상성 분산 설계 필요.
- 부패조 산출 계수 0.25와 파견 산출량은 전부 초안 수치. "하루 한 번 접속" 기준으로 한 런 분량의 재료가 모이는지 실측 필요.
- 접합로 '융합'이 너무 강하면 런 중 파츠 선택이 무의미해질 수 있음 (어차피 나중에 합칠 수 있으니). 계승 스킬 수 제한이나 재료 비용으로 조절.
- 사역 골렘 파견이 "강한 파츠를 전투에서 빼는" 선택이 실제로 고민이 되는지, 아니면 그냥 안 쓰는 파츠만 넣게 되는지 확인 필요.
