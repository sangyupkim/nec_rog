# Project Patchwork — 게임 기획서 v0.3

> 텍스트 UI 기반 턴제 로그라이트. 플레이어는 네크로맨서, 전투 주체는 몬스터 부속으로 조립한 **누더기 골렘**.
>
> 전투는 포켓몬식 커맨드 턴제 — 장착한 파츠가 곧 사용 가능한 스킬 목록이 되고, 매 턴 그중 하나를 골라 싸운다.

---

## 1. 게임 개요

| 항목 | 내용 |
|---|---|
| 플랫폼 | Web (HTML/CSS/JS, 빌드리스 or Vite) |
| 아트 | 이미지 에셋 최소화. 텍스트 + 유니코드 기호 + CSS만으로 표현 |
| 장르 | 커맨드 턴제 전략 로그라이트 / 파츠 크래프팅 |
| 1런 목표 시간 | 25~35분 (Act 1 기준 12~15분) |
| 핵심 판타지 | "적을 죽여 그 시체로 내 병기를 만든다" |

### 1.1 디자인 원칙 (판단 기준)
1. **모든 스탯 변화는 파츠에서 나온다.** 골렘 자체는 빈 프레임이며 고유 스탯이 없다. → 빌드 = 장착 조합.
2. **텍스트가 곧 피드백.** 전투 로그가 UI의 주인공. 수치 변화는 로그 문장에 녹여 쓴다.
3. **매 턴 하나의 결정.** 손패도 자원 관리도 없다. "지금 어떤 스킬을 쓸 것인가" 한 가지에 집중시킨다.
4. **데이터 주도.** 몬스터/파츠/스킬/이벤트는 전부 JSON. 코드 수정 없이 콘텐츠 추가 가능.
5. **모디파이어로 곱셈.** 파츠 40개 × 모디파이어 12개 = 체감 수백 종.

## 2. 코어 루프

```
분기맵 노드 선택
   ↓
전투 (커맨드 턴제 배틀)
   ↓
전리품: 쓰러진 몬스터의 부위 해체 → 파츠 1~3개 중 택1
   ↓
작업대: 골렘 슬롯에 장착 / 교체 / 해체(재료화)
   ↓  (장착 = 스탯 + 사용 가능 스킬 변경)
다음 노드 → ... → 보스
   ↓
사망 or 클리어 → 메타 재화 '영혼재(Soul Ash)' 정산 → 영구 해금
```

**핵심 긴장 구조:** 파츠를 교체하면 스탯은 오르지만 **쓰던 스킬이 사라지고 새 스킬이 들어온다.** 공격력이 더 높은 팔로 갈아끼웠더니 유일한 화염 속성기가 사라져 특정 적을 못 잡게 되는 식이다. 스탯·속성 커버리지·내구도 세 축의 저울질이 이 게임의 주요 의사결정이다.

## 3. 골렘 조립 시스템

### 3.1 슬롯 구성 (5슬롯)

| 슬롯 | 주 기여 스탯 | 스킬 기여 | 비고 |
|---|---|---|---|
| 머리/코어 | 정신력, 통찰 | 0~1개 | 전투 시작 시 발동 패시브 |
| 몸통 | 최대 HP, 방어 | 1개 (방어/버티기계) | 유일하게 비울 수 없음 (필수 슬롯) |
| 좌완 | 공격력 | 1~2개 | 무기 속성 부여 |
| 우완 | 공격력 | 1~2개 | 무기 속성 부여 |
| 다리 | 회피, 속도 | 1개 | 선공 판정 / 유틸 |

- **빈 슬롯 허용** (몸통 제외). 스킬이 줄어드는 대신 스탯 페널티 없이 가벼워지진 않으므로, 빈 슬롯은 기본적으로 손해다. 다만 "썩은 파츠를 억지로 끼우느니 비운다"는 선택지는 성립한다.
- 동시 보유 스킬 수: **5~9개**. 이 목록 전체가 매 턴 화면에 노출된다. 10개를 넘기면 선택 피로가 생기므로 상한 9로 제한.
- 스킬 상한 초과 시(파츠 조합이 9개를 넘길 때) 작업대에서 **봉인할 스킬을 직접 고른다.** 봉인된 스킬은 스탯 기여는 유지하되 전투에서 쓸 수 없다.

### 3.2 스탯 산출식

```
maxHP    = Σ(파츠.hp)                        // 몸통이 60~70% 차지
attack   = Σ(파츠.atk)                        // 스킬 위력에 곱해짐
defense  = Σ(파츠.def)                        // 피해 감산
evasion  = min(60, Σ(파츠.eva))               // % 회피, 하드캡 60
speed    = Σ(파츠.spd)                        // 선후공 판정
focus    = Σ(파츠.focus)                      // 스킬 충전 회복 및 명중 보정
```

데미지 공식:
```
raw   = 스킬.power × (attack / 10) × 랭크배율(공격)
감산  = raw × (대상.defense × 랭크배율(방어)) / (대상.defense × 랭크배율(방어) + 40)
최종  = floor( (raw - 감산) × 속성배율 × 급소배율 ) 
```
- `defense 40`에서 정확히 50% 감산. 방어 스탯은 수확체감이라 탱커 빌드가 무한정 굳지 않는다.
- 급소(치명타): 기본 5%, 배율 1.5.
- 회피 판정은 데미지 계산 이전에 수행 (`evasion - 상대 focus/2`).

### 3.3 내구도 (Integrity)

시체 부속이라는 컨셉을 기계적으로 살리는 장치.

- 모든 파츠는 `integrity` 3~8 보유.
- **전투 종료 시** 해당 전투에서 스킬을 사용한 파츠는 내구도 -1. (사용하지 않은 파츠는 닳지 않는다 → 스킬 선택에 장기적 무게가 실린다.)
- 내구도 5 이하부터 UI에 경고 표시, 2 이하는 적색.
- **내구도 0 → 파츠 소실.** 슬롯이 비고, 해당 파츠의 스탯과 스킬이 즉시 사라진다. 전투 중이라면 전투 종료 후 처리.

#### 소실 방지 / 회복 수단 (네크로맨서의 도구)
파츠 소실은 강력한 압박이므로, 그것을 관리하는 것 자체를 플레이의 축으로 만든다.

| 수단 | 분류 | 효과 |
|---|---|---|
| 역청(Bitumen) | 소모품 | 파츠 1개 내구도 +3 |
| 방부 처리 | 캠프파이어 선택지 | 파츠 1개 내구도 완전 회복 |
| 불멸의 봉인 | 유물(런 지속) | 지정 파츠 1개는 내구도 0이 되어도 소실되지 않고 1에서 멈춤 |
| 시체 방부제 | 유물 | 모든 파츠의 내구도 감소가 2전투당 1회로 감소 |
| 영혼 고정못 | 유물 | 소실 발생 시 1회에 한해 내구도 3으로 복원하고 소모 |
| 해체 | 작업대 | 소실 직전 파츠를 자발적으로 해체해 재료 획득 (손해를 통제된 이득으로 전환) |

> 설계 의도: "강한 파츠는 쓸수록 사라진다"는 자원 압박을 만들되, 네크로맨서의 도구로 그 압박을 관리·연장하는 것이 메타 성장의 방향이 된다.

```json
  "id": "mod_poison",
  "prefix": "독을 품은",
  "tier": 1,
  "stat_multiplier": { "hp": 0.8, "atk": 1.2 },
  "flat_bonus": {},
  "added_skill": "skill_poison_sting",
  "monster_passive": "on_hit_apply_poison_2",
  "weight": 100

```

### 4.2 적용 규칙
- Act 1: 일반 몬스터 40% 확률로 모디파이어 1개 (tier 1만).
- 엘리트: 100%, 1~2개. 보스: 고정 세트.
- 층이 깊어질수록 tier 2 해금, 최대 2개 중첩 (`거대한 불타는 오우거의 팔`).
- 스탯 배율은 **곱연산 후 반올림**, 중첩 시 순차 적용.

### 4.3 동적 네이밍
```
[모디파이어 접두사] + [몬스터 소유격] + [부위]
"독을 품은" + "고블린의" + "다리"
```
데이터에는 `{mod}{owner}{part}` 템플릿만 저장하고 런타임 조립.

## 5. 전투 시스템 (커맨드 턴제)

포켓몬식 1:1 커맨드 배틀. 매 턴 플레이어는 **보유 스킬 목록에서 하나를 선택**하고, 양측의 speed로 실행 순서가 정해진다.

### 5.1 턴 구조
```
전투 시작
  → 코어 패시브 발동 / 적 등장 텍스트
반복 {
  ① 커맨드 선택   : 스킬 / 아이템 / 관찰(적 정보 열람)
  ② 순서 결정     : priority 우선 → speed 비교 → 동률 시 랜덤
  ③ 선공측 행동   : 명중·회피 판정 → 피해/효과 적용 → 사망 체크
  ④ 후공측 행동   : (사망 시 생략)
  ⑤ 턴 종료 처리  : 상태이상 틱 → 지속시간 감소 → 스킬 충전 회복
}
→ 한쪽 HP 0
```

- **적 행동은 예고되지 않는다.** 대신 `관찰` 커맨드로 적의 속성 약점·행동 패턴을 1회 열람할 수 있다(그 턴은 행동 소모). 정보와 템포를 맞바꾸는 선택.
- 도주 없음 (로그라이트 특성상).

### 5.2 스킬 데이터 모델

| 필드 | 설명 |
|---|---|
| `power` | 위력. 0이면 비공격 스킬 |
| `element` | 속성 (아래 표) |
| `accuracy` | 명중률 % (기본 95) |
| `priority` | 우선도. 기본 0, 선제 스킬 +1 |
| `charges` | 전투당 사용 횟수. `null`이면 무제한 |
| `recharge` | N턴마다 충전 1 회복 (focus 스탯으로 단축) |
| `effects` | 상태이상 부여, 랭크 변화, 회복 등 |

**충전(Charge)이 자원이다.** 기본기(발톱 후려치기 등)는 무제한, 강력한 스킬은 전투당 2~3회. 에너지 총량 관리가 아니라 "이 강스킬을 지금 쓸까 아낄까"의 문제로 바뀐다.

### 5.3 속성 상성

7속성. 배율은 유리 1.5 / 불리 0.5 / 무효 0 (극소수).

| 공격 ↓ / 방어 → | 참격 | 타격 | 화염 | 냉기 | 독 | 부패 | 신성 |
|---|---|---|---|---|---|---|---|
| **참격** | – | 1.5 | – | – | – | 0.5 | – |
| **타격** | 1.5 | – | – | 1.5 | – | – | – |
| **화염** | – | – | 0.5 | 1.5 | – | 1.5 | – |
| **냉기** | – | – | 1.5 | 0.5 | – | – | – |
| **독** | 1.5 | – | – | – | 0.5 | 0.5 | – |
| **부패** | – | 1.5 | – | – | 1.5 | 0.5 | 0.5 |
| **신성** | – | – | – | – | – | 1.5 | 0 |

- 골렘의 **방어 속성**은 몸통 파츠가 결정한다. → 몸통 선택 = 방어 상성 선택.
- 골렘의 **공격 속성**은 스킬마다 개별. 양팔을 서로 다른 속성으로 맞추면 대응 폭이 넓어진다. → **다속성 범용 vs 단일속성 특화**가 빌드의 핵심 축.
- 신성 속성은 언데드인 골렘 자신에게 치명적(적 성직자 계열이 사용). 부패는 신성에 무효 — 언데드 컨셉의 상성 반영.

### 5.4 능력 랭크 변화

포켓몬의 능력 랭크와 동일. `공격 / 방어 / 속도 / 회피` 4종, 범위 **-4 ~ +4**.

| 랭크 | -4 | -3 | -2 | -1 | 0 | +1 | +2 | +3 | +4 |
|---|---|---|---|---|---|---|---|---|---|
| 배율 | 0.5 | 0.57 | 0.67 | 0.8 | 1.0 | 1.25 | 1.5 | 1.75 | 2.0 |

- 랭크는 전투 종료 시 초기화.
- 버프 중첩형 빌드(광란의 파츠 등)가 성립하는 근거.

### 5.5 상태이상 8종

| 이름 | 효과 | 지속 |
|---|---|---|
| 중독 | 턴 종료 시 스택만큼 피해, 스택 -1 | 소모형 |
| 화상 | 턴 종료 시 최대HP 5% 피해 + 공격 -25% | 3턴 |
| 균열 | 받는 피해 +50% | 2턴 |
| 마비 | 25% 확률로 행동 불가, 속도 반감 | 3턴 |
| 공포 | 공격 스킬 사용 불가 (보조만 가능) | 1턴 |
| 재생 | 턴 종료 시 최대HP 8% 회복 | 3턴 |
| 가시 | 피격 시 반사 피해 | 전투 지속 |
| 봉인 | 마지막에 쓴 스킬 사용 불가 | 3턴 |

- 동일 상태이상 재부여 시 지속시간 갱신(중독만 스택 누적, 상한 10).

### 5.6 커맨드 UI 원칙
- 스킬 목록은 항상 전부 표시. 숨김·랜덤 요소 없음.
- 각 스킬 옆에 `속성 · 위력 · 남은 충전`을 상시 노출.
- 상성이 **판명된 뒤에는** 유리/불리를 스킬 옆에 아이콘으로 표기(첫 조우 시엔 미표기 → 학습이 진행이 된다).

### 5.7 전투 텍스트 로그
모든 행동은 로그 라인으로 출력. 랜덤 동사 풀로 반복감 완화.
```
> 골렘이 [녹슨 도끼팔]을 휘두른다. 고블린이 14의 피해를 입는다.
> 효과가 굉장했다!
> 독을 품은 고블린의 송곳니가 골렘의 이음새를 파고든다. (9 피해, 중독 2)
> 고블린이 쓰러진다. 남은 것은 아직 경련하는 다리 한 쌍.
```

## 6. 맵 & 진행

### 6.1 구조
- Act 1 = **12층**, 각 층 2~4개 노드, StS식 분기 연결.
- 노드 타입: 전투(⚔) / 엘리트(☠) / 이벤트(?) / 작업대(🔨) / 캠프파이어(🔥) / 보스(👑)

### 6.2 Act 1 층 배치 규칙
```
1층    : 전투 고정
2~3층  : 전투 (모디파이어 확률 진입)
4층    : 이벤트 or 작업대
5층    : 엘리트 최소 1개 보장
6층    : 캠프파이어
7~9층  : 혼합 (전투 40%, 이벤트 25%, 엘리트 15%, 작업대 20%)
10층   : 엘리트
11층   : 캠프파이어 (보스 전 정비)
12층   : 보스
```
- 동일 층에서 같은 타입 노드 3연속 금지.
- 캠프파이어 직전 층에는 전투 노드 보장(회복 자원이 의미 있도록).

### 6.3 캠프파이어 선택지
1. **휴식** — 최대 HP의 30% 회복
2. **방부 처리** — 파츠 1개 내구도 완전 회복
3. **개조** — 파츠 1개에 모디파이어 랜덤 부여 (기존 것 덮어씀, 도박)

내구도 소실이 상시 압박이므로 ①과 ② 사이의 선택이 매번 실질적이다.

  4. 유물 풀 확장 — 특히 §3.3의 내구도 관리 유물들이 주요 해금 대상

`{mod}` 자리에 모디파이어 접두사가 런타임 삽입되고, 없으면 빈 문자열로 치환된다.

### 9.1 적 AI 등급
| 등급 | 방식 |
|---|---|
| 일반 | 가중치 랜덤 + 2연속 동일 스킬 금지 |
| 엘리트 | 가중치 + 조건 규칙(체력 임계, 플레이어 버프 감지 시 해제기 우선) |
| 보스 | 페이즈별 고정 패턴 + 페이즈 전환 시 대사·상성 변화 |

보스가 패턴형인 이유: 정보 공개가 없는 커맨드 턴제에서 보스는 **암기하고 대응하는 대상**이어야 재도전 동기가 생긴다.

```
    combat.js        턴 엔진, 데미지 계산
    effects.js       상태이상 / 능력 랭크 처리
```

## 13. 확정 사항 (v0.3에서 결정)

1. **전투 방식** — 커맨드 턴제(포켓몬형). 카드 드로우/손패/에너지 없음. 파츠가 제공하는 스킬을 매 턴 하나 선택, speed로 선후공 결정, 7속성 상성.
2. **골렘 파괴 = 즉시 런 종료.** 부활 장치 없음.
3. **내구도 0 = 파츠 소실.** 대신 네크로맨서의 도구(유물·소모품·캠프파이어)로 소실을 방지·지연하는 것이 성장의 한 축.
4. **한국어 전용.** i18n 구조 없이 데이터에 한국어 텍스트를 직접 기입.

## 14. 남은 검토 과제

- 속성 상성표는 초안. 시뮬레이션으로 특정 속성 독주 여부 검증 필요.
- 스킬 상한 9개가 실제 플레이에서 과한지 확인 (7개로 낮출 여지).
- '관찰' 커맨드가 턴을 소모할 가치가 있는지 — 무료 열람으로 바꿀지 검토.
- 몸통이 방어 속성을 결정하는 구조 때문에 특정 몸통이 압도적 정답이 되지 않도록 몸통별 상성 분산 설계 필요.
